# DEV-014 — Конвенції коду: стрілкові функції, PascalCase-компоненти

## Мета
Привести код і правила до трьох вимог авторки, без зміни поведінки:
1. Функції й компоненти — **стрілкові `const`** (`export const TaskCard = (props: TaskCardProps) => { … }`), а не function declaration.
2. **Усі** компоненти, включно з shadcn у `shared/ui`, — папка в PascalCase з `index.tsx` (+ `types.ts` / `styles.ts`, лише коли є що туди покласти), як `EmptyState/`.
3. Хуки називаються з префікса `use` — фіксуємо як правило й перевіряємо ESLint.

## Контекст
- Гілка `feat/DEV-014-code-conventions` відгалужена від `feat/DEV-002-ui-kit` (PR #11 ще не злитий), бо рефакторинг торкається файлів DEV-002. Після merge #11 у `stage` гілку треба ребейзнути на `stage`.
- Зараз: `func-style: ["error","declaration"]` (eslint.config.mjs), D-013 і `.claude/rules/code-style.md` вимагають function declaration, shadcn-файли в `shared/ui` — плоскі, lowercase, «в оригінальній формі» (виняток D-013).
- `eslint-config-next` вже вмикає `react-hooks/rules-of-hooks`: виклик `use*` поза компонентом або хуком, чия назва не починається з `use`, — помилка. Окремого правила на імена не додаємо.
- Хуків без префікса `use` у коді немає: єдиний хук `useMediaQuery` названий правильно; `readTheme`/`applyTheme`/`subscribeToTheme` — не хуки.
- Слова авторки: «заміни function declaration на function expression» — розуміємо як стрілкові `const` (підтверджено).

## Acceptance criteria
- AC-1: ESLint вимагає function expression: `func-style: ["error","expression"]` з `allowArrowFunctions`; жодного `function name() {}` у `src`, `test`, `e2e` і конфігах, крім файлів Next.js (`export default` для `page`/`layout`/`not-found` — `const X = …; export default X`).
- AC-2: Кожен компонент у `src/shared/ui` лежить у PascalCase-папці з `index.tsx` (`Alert/`, `Badge/`, `Card/`, `Checkbox/`, `Dialog/`, `Input/`, `Progress/`, `Select/`, `Sheet/`, `Skeleton/`, `Sonner/`, `Switch/`, `Tabs/`, `Textarea/`, `ToggleGroup/`, `Toggle/`, `Tooltip/`); плоских `*.tsx` компонентів не лишилось; імпорти `@/shared/ui/Alert` тощо оновлені.
- AC-3: Правила оновлені: `CLAUDE.md`, `.claude/rules/code-style.md` (стрілкові const, PascalCase для всіх компонентів і shadcn, хуки з `use`), D-023 у `docs/vault/decisions.md` (замінює частину D-013 і виняток для shadcn; D-022 лишається в силі).
- AC-4: Без зміни поведінки: усі наявні тести проходять без правок їхніх assertions (змінюються лише імпорти й форма функцій); `typecheck`, `lint`, `npm test`, `npm run build` і повний E2E зелені.
- AC-5: Тест на конвенції (`test/conventions.test.ts`): у `src` немає плоских `*.tsx` компонентів у `shared/ui` і немає `function`-декларацій у `src/**/*.{ts,tsx}` поза `node_modules`.

## Рішення (технічні, без зміни поведінки)
1. **Форма:** `export const Name = (props: NameProps) => { … }`. Для компонентів із `forwardRef`/generic — той самий стиль (`const X = forwardRef<…>(function-less arrow)`). Хелпери (`cn`, `plural`, `getHeat`…) — теж стрілкові const. Hoisting: функції, що викликаються до оголошення (`noop` у `UiKitView`, внутрішні helper-и), переносимо вище за місце виклику.
2. **Next.js-файли:** `page.tsx`, `layout.tsx`, `not-found.tsx`, `route.ts`: `const Page = () => …; export default Page;` (виняток `no-restricted-syntax` для `src/app` лишається).
3. **shadcn:** компонент переносимо в `Name/index.tsx`, виправляємо імпорти `@/shared/lib/cn`, перетворюємо на стрілкові const. Багатокомпонентні файли (`dialog`, `select`, `sheet`, `tabs`, `card`, `tooltip`, `alert`, `toggle-group`) лишаються одним `index.tsx` з кількома іменованими експортами (не розбиваємо на підпапки: KISS). `components.json` aliases лишаються: CLI створює плоскі файли — після `shadcn add` їх треба переносити; пишемо це в code-style.
4. **ESLint:** `func-style` → `expression` для всього `src`; оверрайд `func-style: off` для `shared/ui` прибираємо; `consistent-type-assertions: off` для `shared/ui/**` лишається (рев'ю DEV-002 радило звузити — звужуємо до `src/shared/ui/*/index.tsx` згенерованих компонентів, а не `Button`/`EmptyState`/`ResponsiveDialog`).
5. **Порядок кроків** (щоб `lint` не червонів посеред роботи): перемістити shadcn → оновити імпорти → конвертувати функції (кодмод-скриптом, потім ручна перевірка) → ввімкнути нове правило ESLint → тест AC-5 → документи.
6. **Не робимо:** перейменування slices/файлів поза `shared/ui`; зміну імен експортів; нові залежності.

## Тестова стратегія
- Наявні unit/jsdom-тести (79) і E2E (28) — регресійна сітка AC-4: не змінюємо assertions, лише імпорти.
- Новий `test/conventions.test.ts` (AC-5) читає дерево `src` і падає на function-декларації й плоскі `*.tsx` у `shared/ui`; перевіряємо його на мутації (повернути одну декларацію → тест червоніє).
- E2E потрібен (план вимагає прогін всього набору), ручне QA ні: UI візуально не змінюється.
