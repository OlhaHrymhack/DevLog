# DEV-012 — Агент D «Радар застряглих»

## Мета

Агент знаходить задачі «в роботі» без змін ≥ 3 днів, ставить діагноз (чекає ревʼю / розмита / завелика / немає активності) і пропонує одну дію: чернетка запиту на ревʼю, чернетка прохання про допомогу, перехід в агента B з автозапуском, «Відкрити задачу». Нічого не надсилає і не змінює. Закриває R-09, R-05, R-18; TC-52…57.

Рішення користувачки 2026-11-22: tier balanced (спека каже strong) для економії токенів; реалізація в головній сесії, рев'ю й security — opus, без Codex. Специфікація — `docs/vault/specs/DEV-012.md`; прототип — `docs/design/prototype.html` (`diagnose`, `runRadar`, `renderAgentD` 691–738; `d-snooze`, `d-act` 1238–1249).

## Рішення

1. `Triage` плоска: `draft` — `string | null` (strict OpenAI), `why` без `oneOf`; `items` ≤ 20.
2. `diagnose` — чиста функція (порядок правил зі спеки), використовується tool-підказкою, mock і fallback; жарти лише поза серйозним режимом (на клієнті й у `why`/`joke` не змішуємо: joke виводиться з причини на клієнті).
3. factCheck: `taskId` лише серед знайдених `find_stale_tasks` (повторний підрахунок із `ctx.tasks` на ту саму мить `ctx.now`), `action` відповідає `cause`, `draft` лише для `draft-*` (20–500), `waiting-review` згадує PR з нотаток (або «PR»), жодних вигаданих PR-номерів і посилань.
4. Fallback — ті самі знайдені задачі з дією `open`, без `draft`; сам проходить factCheck.
5. Порожній результат: зупинка після кроку 2, `items: []`, кроки 3–4 не виконуються (як у прототипі).
6. Ігнорування — `snoozedIds` у стані сесії клієнта (не `localStorage`), передається у вхід агента; reload скидає.
7. «Відхилити» чернетку — тост і закриття діалогу, без запитів у мережу.
