# DEV-004 — REST API задач

## Мета і контекст

Реалізувати REST-контракт із `docs/vault/specs/DEV-004.md` поверх SQLite repository і сервісу DEV-003. Дані та збереження вже в `stage`. UI використовуватиме цей контракт у наступних задачах.

## Acceptance criteria

- AC-1 — створення задачі з дефолтами. Невалідний ввід, серверні поля в тілі й пошкоджений JSON повертають 400.
- AC-2 — читання списку з лічильниками підзадач і деталей із підзадачами й нотатками. Відсутня задача повертає 404.
- AC-3 — часткове оновлення задачі та правила часових полів. Порожнє тіло повертає 400, відсутня задача — 404.
- AC-4 — видалення задачі повертає 204, підзадачі видаляються каскадно. Повторний запит повертає 404.
- AC-5 — фільтр за статусом, сортування й пошук. Невідомі або невалідні query-параметри повертають 400.
- AC-6 — додавання, оновлення й видалення підзадач, додавання нотаток. Підзадача іншої задачі повертає 404.
- AC-7 — встановлення й скидання фокуса. Відсутні та дубльовані ID відхиляються без зміни попередніх рангів.
- AC-8 — єдиний формат помилок і метадані запиту в логах. Внутрішні деталі помилок лишаються на сервері.
- AC-9 — `fetchJson` перетворює помилки HTTP і мережі на типізований `ApiError`.

## Рішення і файли

1. `src/app/api/tasks/**/route.ts` — тонкі обробники. Перевикористати сервіс DEV-003 і наявні Zod-схеми. Додати сувору перевірку API-вводу та окремі схеми для списку підзадач і фокуса.
2. `src/server/http/handler.ts` і `src/shared/api/errors.ts` — формат помилок, request ID, лог статусу й тривалості. Серверні помилки логувати без тіл запитів і ключів.
3. `src/entities/task/api/` — клієнтські запити до маршрутів задач, query keys і HTTP-контракти поруч зі спільними схемами в `src/entities/task/model/`. Загальний транспорт — `src/shared/api/http.ts`. Назовні — публічні експорти слайсу.
4. Використати транзакції repository для фокуса, каскадне видалення і перевірку належності підзадачі до задачі. Для відсутніх ID повертати 404 через типізовану доменну помилку або наявний контракт, який дає змогу відрізнити її від внутрішнього збою.

## Перевірка

- Інтеграційні тести викликають route handlers на ізольованій SQLite-базі й перевіряють AC-1…AC-8. На кожному тесті відповідний префікс `DEV-004 AC-n:`.
- Модульні тести охоплюють спільний транспорт і нормалізацію помилок за AC-9.
- Перед рев’ю — `factory verify DEV-004`. Рев’ю коду й security проводять для одного хешу.

## Маршрут

Balanced (6 балів), реалізація в головній сесії. Security потрібен через валідацію зовнішнього вводу та обробку даних у логах. UI не змінюється.
