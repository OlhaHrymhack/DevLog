# DEV-015 — Конфігуровані ліміти агентів і безпечний dev-smoke

## Мета

Дати змогу один раз безпечно перевірити live-інтеграцію з OpenAI з жорсткими обмеженнями вартості, не змінюючи продуктових значень за замовчуванням (8 викликів, 2048 токенів output, D-029). Рішення користувачки 2026-11-22: ліміти конфігуровані, а smoke виставляє 4 виклики і 400 токенів.

## Контекст

- Специфікація — `docs/vault/specs/DEV-015.md` (у PR #23, до merge читати з гілки `docs/dev008-openai-sdk`); продовжує DEV-008 і D-029.
- У `stage` вже є `createAgentRoute`, `runAgent`, `OpenAIClient`, `selectModelClient`, `getServerEnv`, `createNdjsonResponse`, `readNdjson`. Маршрутів агентів ще немає (DEV-009…012).
- `npm run db:seed` запускається як `node --import tsx … src/server/db/seed/cli.ts`: той самий підхід — для CLI smoke.

## Acceptance criteria

- AC-1 — ліміти конфігуруються й валідуються: `AGENT_MAX_STEPS` 1…8 (default 8), `OPENAI_MAX_OUTPUT_TOKENS` 64…2048 (default 2048). Значення поза діапазоном або нечислове дає помилку старту з назвою змінної.
- AC-2 — `AGENT_MAX_STEPS` обмежує цикл: із 4 після 4 викликів без результату — fallback `stepLimit`; значення більше за `MAX_AGENT_STEPS` не перевищує 8.
- AC-3 — `OPENAI_MAX_OUTPUT_TOKENS` потрапляє в запит (`max_completion_tokens`); без значення 2048; `maxRetries: 0` лишається.
- AC-4 — захист smoke-маршруту до виклику моделі: production → 404; без `AI_SMOKE=1` → 404; чужий хост або `Sec-Fetch-Site: cross-site` → 403; не JSON → 415; demo → 409 `AI_NOT_LIVE`; паралельний запуск → 409 `SMOKE_BUSY`. Жоден випадок не викликає модель.
- AC-5 — smoke-запуск обмежений: запит до моделі має `max_completion_tokens` ≤ 400, не більше 4 викликів, рівно одна фінальна подія, NDJSON у порядку; трасу не пишемо в БД користувача.
- AC-6 — ключ, промпти й дані задач не потрапляють у відповідь, заголовки й логи жодної гілки.
- AC-7 — `npm run smoke:ai` без підтвердження не робить запиту; вивід лише метрики; сервер недоступний → код 2; успіх → 0, помилка маршруту → 1.
- AC-8 — `.env.example` повний (нові змінні з попередженням про вартість `AI_SMOKE`); запис у `decisions.md` — на docs-етапі.

## План реалізації

1. **Env і ліміти.** У `src/shared/config/env.ts` додати `AGENT_MAX_STEPS` і `OPENAI_MAX_OUTPUT_TOKENS` (Zod `coerce`, межі літералами, бо `shared` не імпортує `entities`; тест звіряє їх із `MAX_AGENT_STEPS` і `MAX_COMPLETION_TOKENS`) та `AI_SMOKE` (`"0" | "1"`). Помилка старту називає змінну. `.env.example` — нові змінні.
2. **Проводка.** `createOpenAIClient` приймає `maxOutputTokens` (default 2048) і передає в `toOpenAIRequest`; `selectModelClient` бере його з env. `createAgentRoute`: `maxSteps = min(deps.maxSteps ?? env.AGENT_MAX_STEPS, MAX_AGENT_STEPS)`. Ліміти йдуть у info-лог завершення запуску (числа, не секрети).
3. **Smoke-маршрут.** `src/server/agents/smoke/`: `smokeAgent.ts` (мінімальний агент із `READ_TOOLS`: обрати одну задачу, `factCheck` на існування id, детермінований fallback) і `smokeRoute.ts` (`createSmokeRoute(deps)`): перевірки в порядку NODE_ENV → `AI_SMOKE` → хост (`localhost`, `127.0.0.1`, `[::1]`) і `Sec-Fetch-Site` → `Content-Type` → режим AI → блокування одночасного запуску, потім тіло через `z.strictObject({})`. Ліміти — `min(env, 4)` і `min(env, 400)`. Траса пишеться в тимчасову in-memory БД, не в БД користувача; дані задач читаються з реальної БД лише tools. Тонкий `src/app/api/dev/agent-smoke/route.ts` (`runtime = "nodejs"`, `dynamic = "force-dynamic"`).
4. **CLI.** `src/server/agents/smoke/cli.ts` запускається `npm run smoke:ai` (`node --import tsx …`, без `react-server`-умови й без читання `.env` самим кодом): чисті функції `isConfirmed(answer)` і `summarizeSmokeEvents(events)` (статус, кількість викликів і кроків, код помилки; без `data`), інтерактивне підтвердження через `node:readline/promises`, `readNdjson` для стріму, порт з `PORT` (default 3000). Коди виходу: 0 / 1 / 2.
5. Нових залежностей немає.

## Тестова стратегія

- Unit: env (AC-1), `createAgentRoute` із `AGENT_MAX_STEPS=4` і `ScriptedClient`, що не віддає результат (AC-2), запит `OpenAIClient` на підміненому `create` (AC-3), таблиця guard-ів smoke-маршруту з лічильником викликів моделі = 0 (AC-4), `isConfirmed` і `summarizeSmokeEvents`, код 2 при недоступному сервері (AC-7).
- Інтеграція smoke-маршруту з тимчасовою SQLite та `ScriptedClient`, що імітує live: ліміти, один фінал, порядок подій, відсутність запису в БД користувача (AC-5).
- Приватність: маркер-ключ і текст задачі відсутні у відповідях, заголовках і логах усіх гілок (AC-6).
- Перед рев'ю `factory verify DEV-015`; e2e не потрібен (немає UI). Реальний запуск smoke виконує користувачка (TC-28), вивід — у PR.

## Ризики

- Надто малий `OPENAI_MAX_OUTPUT_TOKENS` обрізає результати агентів (`max_tokens` → fallback): документувати в `.env.example`.
- `AI_SMOKE=1`, залишений увімкненим, дозволяє платні виклики: захист — localhost, 404 у production, блокування одночасного запуску, інтерактивне підтвердження в CLI.
- Перевірка хоста за `Host` не захищає від локального шкідливого процесу: це dev-інструмент, а CSRF-захист решти маршрутів — окрема задача.

## Відкриті питання

Блокерів немає. Для реального smoke потрібен `OPENAI_API_KEY` у `.env.local` і запущений `npm run dev`.
