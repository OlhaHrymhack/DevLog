# DEV-016 — Створення задачі голосом

## Мета й обсяг

Додати голосове введення у звичайний діалог «Нова задача». Специфікація й точний приклад диктування — [DEV-016](../../docs/vault/specs/DEV-016.md). Референс поведінки модалки — [prototype.html](../../docs/design/prototype.html#L1119).

## Реалізація

- У src/features/taskForm додати мікрофон через MediaRecorder, допоміжний текст, стани запису й обробки, звільнення потоку і скасування при закритті. Обмежити запис 60 секундами. Заповнити існуючу форму лише після успішної відповіді.
- Додати до форми необов’язковий дедлайн. Показувати локальний час, передавати на наявний API ISO з часовою зоною. У src/features/taskEdit підтримати зміну й очищення дедлайну через наявний PATCH. Міграція не потрібна.
- Через src/app/api/tasks/voice-draft і src/server/tasks обмежити прийняті формати та розмір запиту (2 MiB), викликати gpt-4o-mini-transcribe після завершення запису й один виклик наявної текстової моделі для заповнення полів. Перевіряти контракт Zod. Аудіо й розшифровку обробляти в пам’яті без збереження або логування. Обидва запити обмежені таймаутом і сигналом скасування.
- У demo-режимі сервер повертає фіксовану чернетку прикладу із локальним дедлайном «завтра о 17:00». Використати чинний режим із серверної конфігурації.

## Перевірки та критерії

| Критерій | Як перевірити |
|---|---|
| DEV-016 AC-1 | Playwright: видимий приклад, ручне створення, доступні дії в мобільному діалозі. |
| DEV-016 AC-2 | Тест запису із підмінним мікрофоном і MediaRecorder: запуск, завершення, ліміт часу й cleanup після закриття. |
| DEV-016 AC-3 | Playwright: підставити чернетку, змінити текст, підтвердити створення, прочитати збережені дані з API. |
| DEV-016 AC-4 | Тест структурованого результату з підмінним OpenAI, разом із перевіркою інструкції для пріоритету, локальної дати та валідації дедлайну. |
| DEV-016 AC-5 | Тести відмови в доступі й помилки API, перевірка порожнього, завеликого аудіо або непідтримуваного формату. |
| DEV-016 AC-6 | Playwright: demo без доступу до мікрофона, заповнення полів і очищення дедлайну через редагування. |

Перевірки Factory: typecheck, lint, unit, Playwright і QA на desktop та mobile. Окреме security review перевіряє поверхню завантаження аудіо, платні виклики та використання розшифровки як даних.

## Рішення

Використати наявний OpenAI SDK і серверну конфігурацію. Чернетка повторно використовує звичайний шлях збереження. Платні виклики в автоматичних тестах підміняються. Точність диктування українською перевіряється окремим коротким записом, якщо доступний live-ключ.
