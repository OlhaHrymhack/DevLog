# DEV-009 — Агент A «План на день»

## Мета

Агент аналізує активні задачі й пропонує top-3 на сьогодні з поясненням кожної та переліком того, що свідомо відкладено. Користувач може закріпити порядок як «Фокус дня». Закриває R-06 (порядок враховує пріоритет, вік, статус і дедлайн, а не лише ранг), R-05, R-18; TC-30…36.

Рішення користувачки 2026-11-22: tier balanced, щоб економити токени (через `factory override`, якщо `classify` дасть strong). Специфікація — `docs/vault/specs/DEV-009.md`; прототип — `docs/design/prototype.html` (`scoreTask`, `explain`, `rulePlan`, `runPrioritize`, `renderAgentA` 592–689; `apply-A`, `apply-A-rule` 1227–1237; бейдж «Фокус #N» 965; `JOKES_A` 592–597).

## Рішення

1. **Результат у strict-сумісному вигляді:** `joke` у `DayPlan` — `string | null` (правило ядра: усі поля required, замість optional — nullable); `items` 1–3, `deferred` 0–3; `why` 20–300 символів. Схема лежить в `entities/agentRun/model/dayPlan.ts` (потрібна і серверу, і UI) з експортом через `index.ts`.
2. **Вхід агента:** `{ serious: boolean }` (strictObject). Дані агент бере сам через tools; `debug` — у конверті запиту, як у ядрі.
3. **Tools:** новий read-only `list_active_tasks` (задачі зі статусом ≠ done: `id, title, status, priority, ageDays, staleDays, dueInHours?, heat, openSubtasks, score`; ліміти `MAX_LISTED_TASKS`/опису як у `list_tasks`) + наявний `get_task`. `list_tasks` для цього агента не підключаємо (меншa поверхня).
4. **Чисті функції агента** (`src/server/agents/prioritize/`): `scoreTask(task, now)` за формулою спеки (вага priority high 3 / medium 2 / low 1; `×10 + min(ageDays,14)×1.2 + min(staleDays,14)×0.8 + in-progress 6 + дедлайн < 48 год 30`), `rulePlan` (пріоритет ↓ → `createdAt` ↑ → in-progress першими; top-3 без пояснень), `explain` (фрази з прототипу), `mockScript`. `getHeat` береться з `entities/task` (потрібен і серверу, і клієнту).
5. **factCheck:** існування й не-done для кожного `taskId`; без дублікатів між `items` і `deferred`; задача з дедлайном < 48 год обов'язково в `items`; `why` містить фактор (ключові слова: пріоритет, вік/днів, в роботі/статус, дедлайн).
6. **Маршрут:** тонкий `src/app/api/agents/prioritize/route.ts` = `createAgentRoute(prioritizeAgent)` (parse → run → NDJSON).
7. **Клієнт:** `features/prioritizeTasks` — хук (`useAgentRun("prioritize")` + мутація застосування фокусу через `PUT /api/tasks/focus`, інвалідація `taskQueryKeys`); `widgets/dayPlanPanel` — `DayPlanPanel` (idle/running/result/fallback/empty/no-data), `FocusConfirmDialog`, згорнута картка < 1024 з `aria-expanded`. Підключення в `TasksListView` у `#agent-a` та мобільну картку; `TaskList` передає `focusRank` у `TaskRow`.
8. **Мікрокопі** — дослівно зі спеки (`copy.uk.ts` слайсу); жарти з `JOKES_A` за температурою лише при `!serious`.
9. Нових залежностей немає. Залежності між слайсами — лише вниз (FSD); барелі `index.ts`.

## Тестова стратегія

- Unit (Vitest): `scoreTask`/`rulePlan` на seed із фіксованим `now`; mock-цикл через `ScriptedClient`; factCheck-матриця; `serious` без жартів; `list_active_tasks` без done-задач і з лімітами.
- Інтеграція: сервіс `setFocus` повторно замінює фокус; видалення задачі прибирає `focusRank`; маршрут агента повертає один фінал і trace у БД (demo).
- Компонентні (jsdom): стани панелі, діалог «Скасувати» без запису.
- E2E (Playwright, demo, без мережі до OpenAI): сценарії AC-4/5/6/7/9. Реального платного запуску не робимо; live-перевірку виконує користувачка smoke-ом за потреби.

## Ризики

- Жива модель може порушити `DayPlan` (довжини `why`, дублікати): ловить Zod + factCheck + 1 повтор + fallback; вартість обмежена лімітами DEV-015.
- Ключові слова для перевірки `why` крихкі: список факторів у константі й покритий тестом; зміна формулювань у `explain` ламає тест, а не мовчить.
- `openSubtasks` треба рахувати з підзадач: якщо `listTasks` їх не повертає, tool читає через `getTask` лише для кандидатів (ліміти 50 задач), без запису в БД.
- Розбіжність прототипу й seed у вагових числах: джерело правди — формула зі спеки й числа AC-1; розбіжність → питання, не підгонка.
