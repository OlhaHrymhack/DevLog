# DEV-005 — Список задач

## Мета

Підключити головний екран DevLog до `GET /api/tasks` після DEV-004. Використати компоненти й токени DEV-002. Відтворити розкладку і стани з `docs/design/prototype.html` за `docs/vault/specs/DEV-005.md`.

## Acceptance criteria

- AC-1 — задачі з API відображаються в порядку пріоритету та дати, рядок підсумку відповідає повному списку.
- AC-2 — фільтр за статусом зберігає загальні лічильники та має доступний стан вибору.
- AC-3 — вибір сортування коректно задає поле та напрямок.
- AC-4 — пошук поєднується з фільтром і сортуванням, скидання повертає повний список.
- AC-5 — loading, error із повтором, порожня БД та відсутність збігів мають окремі стани.
- AC-6 — температура й легенда використовують правила DEV-002, діалог повертає фокус після закриття.
- AC-7 — на 1280 px таблиця, на 768 px дві колонки карток, на 375 px одна колонка та FAB без горизонтального скролу сторінки.
- AC-8 — демо-банер відображає фактичний режим сервера.
- AC-9 — гарячі клавіші працюють із урахуванням поточного фокуса та стану діалогу.
- AC-10 — серйозний режим доступний у dev-панелі, зберігається між перезавантаженнями й не впливає на production.
- AC-11 — панель станів доступна лише в dev і дає змогу відтворити стани UI.
- AC-12 — skip-link, доступні назви кнопок, фокус і група фільтрів працюють із клавіатурою.

## Реалізація

1. Перевикористати `entities/task/api/taskApi.ts`, query keys і контракти DEV-004. TanStack Query тримає серверний стан, UI бере порядок та фільтрацію з API. Повний список використати для стабільних лічильників і підсумку.
2. Зібрати головну сторінку, шапку, банер, тулбар і список у `views/tasksList`, `widgets/` і `features/`. Перевикористати `TaskRow`, `HeatBadge`, `ResponsiveDialog`, теми й токени. Референси в HTML: `renderShell`, `renderList`, `renderFilters`, `renderTasks`, `openLegend` і `openStates`.
3. Режим для банера отримувати через наявний `/api/health`. У разі невдалої відповіді режим вважати невідомим. У повідомленнях про помилки використовувати нейтральну мікрокопі відповідно до D-015.
4. Зберегти місця під агентів A/D і точки підключення діалогів DEV-006. Серверні мутації для цих UI-діалогів і запуск агентів належать наступним задачам.

## Перевірка і маршрут

- Перевірити поведінку фільтрів, сортування, мікрокопі й production-обмежень цільовими тестами. Playwright покриває живий API на окремій seed-БД, стани, адаптивність і клавіатуру.
- `factory verify DEV-005` перед рев’ю, `factory verify DEV-005 --full` до фінального погодження. Зіставити UI з прототипом за допомогою браузерного QA.
- Balanced, 6 балів. Головна сесія для реалізації, Sonnet для незалежного рев’ю.
