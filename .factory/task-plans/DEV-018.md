# DEV-018 — лічильник спроб агентів

Публічне демо має три окремі спільні квоти по 50 запусків: «План на день», «Радар застряглих» та «Голосовий ввід». Усі відвідувачі разом можуть використати до 150 запусків.

## Критерії приймання

- AC-1. У шапці списку й деталей задачі є кнопка «Спроби AI». Панель показує три рядки з кількістю використаних і доступних спроб та сумарний залишок із 150. Пояснення вказує, що ліміт спільний для всіх відвідувачів. Панель доступна на мобільному та з клавіатури.
- AC-2. У середовищі з квотою сервер атомарно резервує до 50 запусків окремо для кожної з трьох функцій. З 51-го запуску відповідний маршрут повертає `429` до будь-якого виклику OpenAI. Резервування зберігаються між деплоями. Агреговане читання використовує ті самі ліміти й лічильники, трактує відсутність рядка як 0 і не резервує спроб.
- AC-3. Дані оновлюються під час відкриття та періодично, доки панель відкрита. Під час завантаження та помилок UI показує відповідний стан і дозволяє повторити запит. Середовище з вимкненою квотою показує, що ліміту немає.
- AC-4. У середовищі з квотою AI-декомпозиція й AI-статус-апдейт недоступні через UI і прямі запити. Радар не запускає декомпозицію автоматично. Ручні підзадачі, нотатки та редагування залишаються доступними. Локальний запуск без квоти зберігає всі AI-функції.

## Реалізація та перевірки

- Один запит до наявної таблиці, маршрут `GET /api/agents/quota` з `Cache-Control: no-store` і наявний адаптивний діалог у `AppHeader`. Використати спільну конфігурацію дозволених типів і лімітів для читання й атомарного резервування. Міграція БД не потрібна.
- Перевірити 50/51 для кожного типу, суму 150, конкурентні запити, збереження лічильників, нуль викликів моделі після блокування й повторне читання без зміни залишку. Перевірити відмову для обох інших маршрутів і мобільний UI, включно з оновленням чисел у demo Preview. Прогнати `factory verify DEV-018 --full`.
