# DEV-010 — Агент B «Декомпозиція»

## Мета

Агент розбиває задачу на 3–6 підзадач з оцінкою часу й поясненням; нечітку задачу спершу уточнює. Підзадачі створюються лише ті, що обрав користувач, і лише після «Створити». Закриває R-07, R-05, R-18; TC-37…44.

Рішення користувачки 2026-11-22: tier balanced (спека каже strong), щоб економити токени; реалізація в головній сесії, рев'ю й security — opus. Специфікація — `docs/vault/specs/DEV-010.md`; прототип — `docs/design/prototype.html` (`TEMPLATES`, `isVague`, `pickTemplate`, `runDecompose`, `renderAgentB` 740–803; `apply-B`, `b-toggle`, `reset-B` 1253–1262, 1291; clarify submit 1310–1316; `goto-B` 1251).

## Рішення

1. `Decomposition` для OpenAI strict — discriminated union не підтримується надійно, тому на межі моделі схема плоска: `{ kind: "clarify" | "subtasks", questions: string[] | null... }`-подібна форма з nullable-полями, а в Zod — рефайн, що перетворює на union за спекою. Остаточну форму фіксуємо тестом strict-сумісності (як у DEV-009).
2. Дублікати: нормалізація (lowercase, без пунктуації), дублікат — збіг перших 12 символів або вкладення одного в інший; перевіряється між пунктами й проти наявних підзадач.
3. Уточнення зберігається нотаткою **до** нового запуску (`POST /notes`), щоб агент читав його через `get_task`.
4. Створення підзадач — лише через `POST /api/tasks/:id/subtasks` після «Створити»; агент нічого не пише.
5. Fallback `generic` — 4 пункти зі спеки; сам проходить factCheck (3–6, без дублів з наявними — при збігу відкидаємо збіги, лишаючи ≥ 3 за рахунок розширеного generic).
6. `isVague` живе в `entities/task/model` (клієнт) і імпортується серверним tool через публічний API entity.

## Acceptance criteria (зі специфікації, нумерація збережена)

- **AC-1** Чітка задача → 3–6 підзадач з оцінкою й поясненням. [U] mock на t7 (upgrade) → 5 пунктів, кожен з `estimate` і `rationale` (TC-37). [E] t7 → «Розбити на підзадачі» → 4 кроки → 5 пунктів з чекбоксами.
- **AC-2** Нечітка задача → clarify без генерації. [U] t8 → `kind: "clarify"`, 2 питання; крок «Згенерувати» не виконувався (TC-38). [E] t8 → alert «Опис короткий…» → запуск → питання й форма.
- **AC-3** Уточнення зберігається нотаткою й продовжує генерацію. [E] відповідь → нотатка «Уточнення для декомпозиції: …» → шаблон tests (4 пункти) (TC-39). [U] `clarify` при наявному `clarification` → порушення factCheck.
- **AC-4** Нічого не створюється без підтвердження; створюються лише обрані. [E] до «Створити» кількість підзадач не змінилась (TC-40); зняти 1 з 5 → «Створити 4 підзадачі» → рівно 4 з бейджем «AI» (TC-41); зняти всі → кнопка disabled.
- **AC-5** Дублікати відкидаються. [U] factCheck на t1: «Зняти heap snapshot» → дублікат (вкладення); «Відтворити проблему стабільно» → ні; два однакові пункти → дублікат (TC-42). [U] 1 або 10 пунктів → порушення схеми (TC-43).
- **AC-6** Хибний кейс → fallback generic. [U] `forceInvalidOutput` → 2 спроби з дублікатами → fallback з 4 пунктами. [E] dev-панель → alert «Відповідь агента відхилено», шаблон, «Створити 4 підзадачі» працює.
- **AC-7** Скасування й стоп. [E] «Скасувати» в результаті / clarify → idle, нічого не створено (TC-44); «Зупинити» → idle.
- **AC-8** Автозапуск. [E] `/tasks/t3?tab=decompose&autorun=1` → вкладка «Підзадачі», агент уже працює; «Розбити з AI» у порожньому списку підзадач → те саме.
- **AC-9** Applied. [E] після створення — «Створено N підзадач…» і «Розбити ще раз»; повторний запуск не пропонує вже створені пункти.
