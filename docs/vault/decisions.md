# Журнал рішень (append-only)

> Лише дописувати в кінець. Переглянуте рішення — новий запис «Supersedes D-xxx». Hook блокує зміну старих записів.

## D-001 Фабрика розробки: lean-варіант на нативних механізмах Claude Code + gstack
- Дата: 2026-11-21
- Рішення: orchestrator — головна сесія (skill `/factory`), 7 subagents, gates через hooks + CLI `.factory/bin/factory.mjs` (0 залежностей), gstack глобально.
- Причина: бюджет ТЗ 8–10 год; reviewer-и ТЗ не повинні нічого встановлювати; не дублювати gstack.
- Альтернативи: повна фабрика з окремим orchestrator-агентом; team mode gstack у репо.
- Пов'язано: [[architecture/factory]]

## D-002 Evidence прив'язаний до tree hash, а не до commit SHA
- Дата: 2026-11-21
- Рішення: ключ evidence — `git write-tree` робочого дерева без `.factory/` і `docs/vault/`.
- Причина: до коміту SHA не існує; будь-яка зміна коду автоматично робить review/tests застарілими.
- Наслідок: звіти агентів треба зберігати поза репо, інакше вони самі змінюють hash (знайдено selftest-ом).

## D-003 Approval — лише з промпту користувача
- Дата: 2026-11-21
- Рішення: `UserPromptSubmit` hook ловить `APPROVE <ID>` / `APPROVE-FINAL <ID>`; запис approvals агентом заблоковано.
- Причина: агент не може підробити текст, який ввела людина; slash-команда тут ненадійна (розгортається як skill).

## D-004 Git hooks через core.hooksPath замість Husky
- Дата: 2026-11-21
- Рішення: `.githooks/` + `git config core.hooksPath .githooks` (у DEV-001 — через npm `prepare`).
- Причина: без зайвої залежності; працює ще до появи package.json.

## D-005 Fast-задачі пропускають етап QA
- Дата: 2026-11-21
- Рішення: для tier fast — без approval плану і без QA; review (opus), tests і фінальний approval лишаються.
- Причина: бюджет ТЗ; дрібні зміни не варті браузерного QA. Погоджено користувачем.

## D-006 Гілки: feature → stage → main
- Дата: 2026-11-21
- Рішення: фіча-гілки → PR у `stage`; merge у stage і stage → main (prod) робить лише користувач. Push у `stage`/`main` заблоковано guard-ом (`branches.protected`).

## D-007 gstack: лише skills з Master Prompt
- Дата: 2026-11-21
- Рішення: gstack 1.102.1 (stable) глобально; лишено 18 skills зі специфікації + `freeze`/`unfreeze` (залежність `/guard`); решту посилань прибрано з `~/.claude/skills`. `/test` у gstack не існує (це тест-сьют репо). Конфіг: proactive off (skills не запускаються самі в обхід /factory), routing off, update_check off (версія не дрейфує), telemetry off.
- Наслідок: `/gstack-upgrade` або повторний `./setup` поверне всі skills — після оновлення прибрати знову.

## D-008 Cross-family review для strong-задач
- Дата: 2026-11-21
- Рішення: strong-задачі (включно з ескальованими) потребують другого рев'ю через OpenAI Codex (`/codex`); evidence kind `codex`, gate 3 без нього не проходить.
- Причина: Claude-модель, що рев'ює Claude-код, має спільні сліпі зони. Ризик: код задачі надсилається в OpenAI.

## D-009 Модель Codex для cross-family review задається на рівні проєкту
- Дата: 2026-11-21
- Рішення: `GSTACK_CODEX_MODEL=gpt-6.2-sol` у `.claude/settings.json` (env). Глобальний `~/.codex/config.toml` не змінюємо.
- Причина: глобальна модель `gpt-5.4` не підтримується при вході через ChatGPT (перевірено `codex exec`); `gpt-6.2-sol` відповідає. Інші проєкти користувачки не зачіпаються.

## D-010 Репо лишається приватним, без branch protection
- Дата: 2026-11-21
- Рішення: приватний репозиторій; branch protection / rulesets недоступні на безкоштовному плані.
- Наслідок: захист гілок — guard-и Claude Code, `.githooks/`, CI; перед merge користувач вручну перевіряє зелений CI. Для здачі ТЗ — надати доступ рецензентам.

## D-011 Усі зміни — лише через PR у stage з approval користувача
- Дата: 2026-11-21
- Рішення: будь-яка зміна (код, docs, фабрика) — фіча-гілка від `stage` → PR `--base stage`; коміти прямо в `main`/`stage` заблоковано guard-ом, `gh pr create` без `--base stage` заблоковано. Merge — лише користувач після approval.
- Причина: прогалина — bootstrap-коміт фабрики пішов прямо в main; після першого push default branch на GitHub = main, і PR без `--base` пішов би в prod.
- Виняток: перші два коміти фабрики (`fb7639f`, `048b5f6`) — bootstrap до появи `stage`.

## D-012 Автоматичний журнал спрацювань контролю
- Дата: 2026-11-21
- Рішення: guard і hook `PermissionDenied` пишуть кожне блокування / ask / відмову в `.factory/guard-log.jsonl` (маскування секретів, обрізання до 300 символів); файл комітиться.
- Причина: до цього автоматично логувались лише промпти користувачки, а випадки зупинки агента — вручну і неповно (2 з 11). Для AGENT_LOG потрібні саме вони.

## D-013 Стайл-гайд: FSD на клієнті, DDD на сервері, function declaration
- Дата: 2026-11-21
- Рішення: клієнт — Feature-Sliced Design (`views → widgets → features → entities → shared`, public API через `index.ts`); сервер — DDD-модулі в `src/server/`; загальні утиліти — `src/shared/lib/`. Компоненти — function declaration з іменованим експортом, папка в PascalCase (`TaskCard/index.tsx`, `types.ts`, `styles.ts` зі стилями через `cva`). shadcn-компоненти в `shared/ui` — виняток. Правила — `.claude/rules/code-style.md`, enforcement ESLint-ом у DEV-001.
- Причина: вимога користувачки (DDD, KISS, FSD, окремі файли типів і стилів); FSD задумана для UI, тому сервер (агенти, репозиторій) — окремим DDD-шаром. Шар `pages` FSD перейменовано у `views` через конфлікт із Next.js.
- Наслідок: розділ «Структура» в CLAUDE.md замінено; `lib/` → `server/` і `shared/lib/`.

## D-014 Дизайн-система з Claude Design і адаптація до архітектури
- Дата: 2026-11-21
- Рішення: джерело правди для UI — `docs/design/` (DESIGN.md, tokens.css, prototype.html); агент D — «Радар застряглих». Відхилення від DESIGN.md: імена slices — camelCase (стайл-гайд, D-013); логіка агентів і детерміновані правила — на сервері (`src/server/agents`), клієнт лише викликає `/api/agents/*`; серверний стан — TanStack Query; живі кроки агента — NDJSON-стрім, «Зупинити» — abort. UI Kit — окрема задача DEV-002 зі сторінкою `/ui-kit`. Понад ТЗ беремо: температуру задачі, пошук і гарячі клавіші, «Серйозний режим», «Зупинити».

- Ризик: обсяг понад бюджет ТЗ — порядок вирізання зафіксовано в `.factory/tasks.md`.

## D-015 Специфікації задач і рішення за прототипом
- Дата: 2026-11-21
- Рішення: детальні специфікації задач — `docs/vault/specs/DEV-xxx.md` (вхід для `/factory`, AC переносяться в план без зміни нумерації). Погоджено користувачкою: (1) ручного додавання підзадачі немає — лише агент B після підтвердження; (2) «Серйозний режим» у production без перемикача (лише dev-панель), гумор у production увімкнений, але ніколи не в помилках, видаленні й апдейтах для менеджера; (3) у live-режимі агенти самі викликають read-only tools і завершують `submit_result`; demo — той самий цикл `runAgent` зі скриптованим клієнтом; fault injection лише поза production; «Ігнорувати» в D — стан сесії на клієнті; фокус дня — `focusRank` у БД.
- Причина: відповідність прототипу і ТЗ, KISS; один цикл для demo і live робить demo чесною демонстрацією агентності.
- Ризик: відхилення від DESIGN §1.4 («вмикається перемикачем») — пояснюємо в README.
