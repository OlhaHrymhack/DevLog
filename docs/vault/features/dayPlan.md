# План на день (Агент A, prioritize)

- **Що зроблено:** агент A аналізує активні задачі (status ≠ done), пропонує top-3 на сьогодні з поясненням кожної і що відкладено; користувач може закріпити порядок як «Фокус дня». Супутньо (PR #24, DEV-015): конфігуровані ліміти агентів і dev-only smoke — [[decisions]] D-030.
- **Acceptance criteria:** AC-1…AC-9 зі [[specs/DEV-009]]: (1) `scoreTask` враховує кілька факторів; (2) mock-агент проходить цикл tools і повертає валідний `DayPlan`; (3) factCheck (існування задач, дублікати, термінові в `items`, фактор у `why`); (4) хибний результат → fallback `rulePlan`; (5) застосування фокусу лише після підтвердження; (6) порожній список; (7) зупинка, перегенерація, «Відхилити»; (8) серйозний режим без жартів; (9) адаптив. Результати перевірок — у evidence задачі (`factory status`), тут не дублюються.
- **Як працює:**
  - `src/server/agents/prioritize/`: `scoreTask.ts`, `rulePlan.ts`, `activeTasks.ts`, `prioritizeAgent.ts`; ядро — `server/agents/core` ([[decisions]] D-029).
  - Вага: `priority×10 + min(вік,14)×1.2 + min(без змін,14)×0.8 + 6 (in-progress) + 30 (дедлайн < 48 год)` — D-031.
  - Fallback `rulePlan`: термінові першими → пріоритет → старіші → in-progress; без пояснень (фіксований `RULE_PLAN_WHY`).
  - Стани панелі: idle, running, result, fallback; «немає даних» і «немає активних задач».
  - Фокус дня: `PUT /api/tasks/focus` лише після підтвердження в діалозі; агент сам дані не змінює.
- **Обмеження / що свідомо не зроблено (follow-up з PR #25):**
  - немає CSRF/Origin-перевірки на `/api/agents/*`;
  - `FACTOR_PATTERN` у factCheck спрацьовує на підрядки;
  - `list_active_tasks` не повертає ознаку `truncated`;
  - текст fallback не залежить від причини (двічі невалідна відповідь, ліміт кроків тощо);
  - порядок fallback (urgent-first) розходиться зі спекою і копією в UI («пріоритет → вік → статус») — чекає рішення користувачки.
- **Метрики:** tier balanced, 1 цикл доопрацювання, 2 провали verify, 1 блокувальне рев'ю, ~0.7 год до PR.
