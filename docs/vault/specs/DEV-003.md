# DEV-003 — Шар даних і seed

**Tier:** strong · **Залежить:** DEV-001 · **Розблоковує:** DEV-004, DEV-008 · **Агенти:** стандарт + Codex
**Покриття ТЗ:** R-01 (поля задачі), R-03 (зберігання між перезавантаженнями) · TC-17, TC-18, TC-19 з [[product]]

## Мета
Персистентне сховище з єдиним доступом через repository, Zod-контракти сутностей, авто-міграції і демо-дані, що покривають усі сценарії UI та агентів.

## Скоуп
**Входить:** Drizzle-схема, міграції, авто-міграція при старті, repository, доменний сервіс задач (правила `updatedAt`), Zod-схеми в `entities/*/model`, `db:seed`.
**Не входить:** HTTP (DEV-004), агенти (DEV-008 — але таблиці `agent_runs`/`agent_steps` створюються тут).

## Реалізація
1. Залежності: `better-sqlite3`, `drizzle-orm`, `drizzle-kit` (dev), `nanoid` (id). Пояснення в PR: SQLite — файл, нуль інфраструктури, `npm run dev` без Docker.
2. Схеми таблиць лежать у `src/server/tasks/schema.ts` та `src/server/agentRuns/schema.ts`. `src/server/db/schema.ts` експортує їх для спільних міграцій:
   | Таблиця | Поля |
   |---|---|
   | `tasks` | `id` text pk · `title` text · `description` text · `status` `todo\|in-progress\|done` · `priority` `low\|medium\|high` · `createdAt` text ISO · `updatedAt` text ISO · `dueAt` text ISO null · `focusRank` int null |
   | `subtasks` | `id` · `taskId` fk → tasks **on delete cascade** · `title` · `status` (`todo\|in-progress\|done`, UI перемикає todo ↔ done) · `source` `user\|ai` · `estimate` text null (напр. «~2 год») · `rationale` text null · `position` int · `createdAt` |
   | `notes` | `id` · `taskId` fk cascade · `text` · `createdAt` |
   | `agent_runs` | `id` · `kind` `prioritize\|decompose\|status-update\|stuck-radar` · `taskId` null · `status` `running\|result\|clarify\|fallback\|stopped\|error` · `mode` `live\|demo` · `startedAt` · `finishedAt` null · `resultJson` null · `errorJson` null |
   | `agent_steps` | `id` · `runId` fk cascade · `index` int · `type` `model\|tool\|validation` · `label` · `state` `done\|fail` · `detail` null · `payloadJson` null (без повних промптів на рівні info-логів) · `createdAt` |
   Індекси: `tasks(status)`, `subtasks(taskId)`, `notes(taskId)`, `agent_steps(runId)`.
3. `src/server/db/client.ts` — синглтон з'єднання (`globalThis` у dev через HMR), `PRAGMA foreign_keys=ON`, `journal_mode=WAL`; створює теку `data/`; запускає `migrate()` один раз. `data/` — у `.gitignore`.
4. **Zod-контракти** (`entities/task/model/schemas.ts`, `entities/note/model/schemas.ts`, `entities/agentRun/model/schemas.ts`):
   - `TaskStatusSchema`, `TaskPrioritySchema`;
   - `TaskSchema` (повна, з `subtasks[]`, `notes[]`), `TaskCreateInputSchema` (`title` trim 3–120, `description` trim 5–2000, `status` default `todo`, `priority` default `medium`, `dueAt?` ISO), `TaskUpdateInputSchema` (partial, хоча б одне поле; `createdAt`/`id` заборонені — `.strict()`);
   - `SubtaskSchema`, `SubtaskCreateInputSchema` (`title` 1–200, `source`, `estimate?`, `rationale?`), `NoteSchema`, `NoteCreateInputSchema` (`text` trim 1–2000).
   - Типи — лише `z.infer`.
   - Межі довжин узгоджені з формою прототипу (назва ≥ 3, опис ≥ 5) — це вирішує відкрите питання з [[product]] §7.
5. `src/server/tasks/repository.ts` — **єдиний** SQL-доступ: `listTasks({status?, q?, sort, order})`, `getTask(id)` (з підзадачами й нотатками), `createTask`, `updateTask`, `deleteTask`, `addSubtasks(taskId, items[])` (транзакція), `updateSubtask`, `deleteSubtask`, `addNote`, `setFocus(taskIds[])` (транзакція: усім `null`, потім 1..N), `findStale({ minDays, now })`. Операції трасування `createRun`, `appendStep`, `finishRun` і `listRunSteps` належать `src/server/agentRuns/repository.ts`.
   - Сортування в SQL: пріоритет через `CASE` (high=3, medium=2, low=1), при рівності — `createdAt DESC`; дата — `createdAt`.
   - Пошук: `LIKE` по `title || ' ' || description`, case-insensitive, з екрануванням `%`/`_`.
6. `src/server/tasks/service.ts` — доменні правила:
   - `updatedAt` оновлюється при зміні статусу, пріоритету, назви, опису, при додаванні / перемиканні / видаленні підзадачі, при додаванні нотатки; **не** оновлюється від `setFocus`;
   - `createdAt` не змінюється ніколи;
   - видалення задачі каскадно видаляє підзадачі й нотатки.
   - `now` передається параметром (`clock`), за замовчуванням `() => new Date()`.
7. **Seed** `npm run db:seed`: спільний сценарій у `src/server/db/seed/` очищає історію агентів, а `src/server/tasks/seed/` замінює задачі демоданими з `data.ts`. Операції виконуються в одній транзакції. Seed вставляє **12 задач з `mockTasks()` прототипу** (рядки 474–497) з датами відносно `now`: t1…t12 з тими ж назвами, описами, статусами, пріоритетами, `createdAt`/`updatedAt` (дні тому), `dueAt` t2 = now + 20 год, підзадачами (статус, source `user`) і нотатками. Ідемпотентний (повторний запуск дає ті самі 12).
   Покриття: alarm (t2), fire (t7), hot (t1), warm (t3, t8, t12), calm (t5, t10), fresh (t4, t9), done (t6, t11); D: t1 → «Чекає на ревʼю», t3 → «Розмита», t12 → «Завелика»; B: t8 — нечітка.
8. `npm run dev` на порожній БД не сідить автоматично (порожній стан теж треба показати); README (DEV-013) пояснює `db:seed`.

## Acceptance criteria і тест-кейси
Тести — на тимчасовій БД (`:memory:` або файл у tmp), з фіксованим `now`.
- **AC-1** Перший запуск створює файл БД і схему.
  - [I] порожня тека → `getDb()` → таблиці існують; повторний виклик не падає.
- **AC-2** CRUD задачі через repository зберігається між з'єднаннями.
  - [I] create → закрити з'єднання → відкрити → `getTask` повертає ту саму задачу (TC-17).
- **AC-3** Zod-схеми відхиляють невалідне.
  - [U] title "  ab " → помилка; description 4 символи → помилка; status "blocked" → помилка; update з `createdAt` → помилка (strict); update `{}` → помилка.
- **AC-4** Правила `updatedAt` / `createdAt`.
  - [I] зміна статусу → `updatedAt` = now; додавання нотатки / перемикання підзадачі → `updatedAt` = now; `setFocus` → `updatedAt` без змін; `createdAt` незмінний після всіх операцій.
- **AC-5** Сортування і фільтр у repository.
  - [I] priority desc: high → medium → low, при рівності новіші вище; asc — навпаки за пріоритетом; date desc/asc за `createdAt`; `status=in-progress` — лише такі; `q="пам"` знаходить t1 по назві, `q="OOM"` — по опису; `q="%"` не повертає все.
- **AC-6** Каскадне видалення.
  - [I] delete t1 → підзадач і нотаток t1 у БД немає.
- **AC-7** `setFocus` атомарний.
  - [I] setFocus([t2,t7,t1]) → ранги 1,2,3; setFocus([t9]) → t9=1, решта null.
- **AC-8** `findStale` повертає in-progress з ≥ N днями без змін.
  - [I] на seed з фіксованим now: `minDays: 3` → t1, t3, t12 (не t9 — свіжа, не t2 — todo).
- **AC-9** Seed покриває всі рівні температури і ідемпотентний.
  - [I] після seed `getHeat` по 12 задачах дає всі 7 рівнів; двічі seed → 12 задач (TC-19).
- **AC-10** Трасування агентів записується.
  - [I] createRun → appendStep×3 → finishRun → кроки в порядку `index`, run має `finishedAt`.
