# DEV-006 — Створення / редагування / видалення задачі

**Tier:** balanced · **Залежить:** DEV-005 · **Розблоковує:** DEV-007 · **Агенти:** стандарт + 🎨 + E2E (CRUD)
**Покриття ТЗ:** R-01 (створення, редагування, видалення; поля title, description, status, priority, createdAt) · TC-01, TC-02, TC-07, TC-08 з [[product]]

## Мета
Повний UI-цикл CRUD з однією Zod-схемою для форми й API, доступними діалогами і bottom sheet на мобілці.

## Референс у прототипі
`openTaskForm` (1116–1133), `submitTaskForm` (1134–1155), `askDelete` (1156–1166), `confirmDialog` (1100–1104), `openModal` / `closeModal` (1086–1098), фокус-пастка (1318–1329), CSS форм 286–296 і оверлеїв 298–313.

## Реалізація
1. `features/taskForm` — `TaskForm` (react-hook-form + `zodResolver(TaskCreateInputSchema)` з `entities/task`):
   - «Назва \*» — input, placeholder «Наприклад: Виправити флакі тест», autofocus; помилка «Назва обовʼязкова, щонайменше 3 символи»;
   - «Опис \*» — textarea, placeholder «Що потрібно зробити і навіщо»; помилка «Опишіть задачу хоча б одним реченням»; живий hint, якщо 0 < довжина < 40: «✦ Опис короткий: агент декомпозиції попросить уточнення.» (колір `--ai`);
   - «Статус» — сегмент-радіо «До роботи / В роботі / Готово» (default «До роботи»); «Пріоритет» — «Високий / Середній / Низький» (default «Середній»);
   - примітка: створення — «createdAt проставляється автоматично.»; редагування — «Створено <дата>. Дата створення не редагується.»;
   - помилки: червона рамка (`aria-invalid`), текст під полем (`aria-describedby`), фокус на **перше** невалідне поле;
   - серверна 400 → `fieldErrors` мапляться на поля; інша помилка → тост «Не вдалося зберегти. Спробуйте ще раз», діалог лишається відкритим, введене не губиться.
2. `features/taskCreate` — `CreateTaskDialog` + `useCreateTask` (mutation → invalidate `tasks`); заголовок «Нова задача», кнопки «Скасувати» / «Створити»; тост «✨ Задачу створено. Поки що вона 🥒 свіжа» / серйозно «Задачу створено». Відкривається з «Нова задача», FAB, гарячої клавіші, empty-стану.
3. `features/taskEdit` — `EditTaskDialog` + `useUpdateTask`; «Редагувати задачу», «Зберегти»; тост «Зміни збережено»; якщо задача була гаряча (rank ≥ 2, не done) і стала done → «🧯 Пожежу загашено. Звіт для страхової не потрібен» / «Задачу закрито». Надсилаються лише змінені поля.
4. `features/taskDelete` — `DeleteTaskDialog` + `useDeleteTask`: «Видалити задачу?», текст ««<назва>» буде видалено разом із N підзадачами і M нотатками. Цю дію не можна скасувати.» (правильні відмінки через `plural`), «Скасувати» / «Видалити» (danger); **без жартів у тексті діалогу**; фокус на кнопці підтвердження; тост «🪦 Видалено. Ніхто й не помітить» / «Задачу видалено». З деталей задачі — перехід на `/`.
5. `shared/ui/ResponsiveDialog` (з DEV-002): ≥ 768 — модалка 520px; < 768 — bottom sheet, дії sticky внизу на всю ширину; клік по оверлею і Esc закривають; фокус повертається на елемент, що відкрив.
6. Оптимістичних оновлень не робимо (KISS): після успіху — invalidate і закриття. Кнопка сабміту disabled під час запиту.

## Acceptance criteria і тест-кейси
- **AC-1** Створення задачі.
  - [E] «Нова задача» → заповнити → «Створити» → задача на початку списку при сортуванні «Дата: спершу нові», тост, діалог закрито (TC-01).
- **AC-2** Валідація форми.
  - [U] `TaskForm`: назва «ab» → помилка під назвою і фокус на назві; порожній опис при валідній назві → фокус на описі; обидва невалідні → фокус на назві (TC-02); опис 10 символів → hint про короткий опис видно; 40+ → hint немає.
  - [E] сабміт порожньої форми → 2 помилки, запит не відправлено (`page.route` не викликано).
- **AC-3** Серверні помилки показуються біля поля.
  - [U] мок 400 з `fieldErrors.title` → текст під назвою; мок 500 → тост, введене збережене.
- **AC-4** Редагування.
  - [E] «Редагувати «…»» у рядку → поля заповнені → змінити пріоритет → «Зберегти» → рядок оновлено, тост «Зміни збережено» (TC-07).
  - [U] надсилається лише змінене поле; гаряча задача → done → тост «Пожежу загашено…» (серйозно — «Задачу закрито»).
- **AC-5** Видалення з підтвердженням.
  - [E] «Видалити «t1»» → діалог «… разом із 2 підзадачами і 1 нотаткою …» → «Скасувати» → задача є; ще раз → «Видалити» → задачі немає, тост (TC-08).
  - [U] у тексті діалогу немає емодзі навіть з `serious=false`.
- **AC-6** Доступність діалогів.
  - [E] Tab не виходить за межі діалогу; Esc закриває; фокус повертається на кнопку-відкривач; `role="dialog"`, `aria-modal`, `aria-labelledby`.
- **AC-7** Мобілка.
  - [E] 375px → діалог знизу (bottom sheet), кнопки дій видно без скролу при відкритій клавіатурі (sticky).

## Ризики / питання
- `react-hook-form` + `@hookform/resolvers` — нові залежності; альтернатива — власний `useZodForm` (≈ 40 рядків). Вибір фіксує architect.
