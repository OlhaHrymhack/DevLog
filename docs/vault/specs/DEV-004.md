# DEV-004 — REST API задач

**Tier:** balanced · **Залежить:** DEV-003 · **Розблоковує:** DEV-005…007, DEV-009/010 (apply) · **Агенти:** стандарт + 🔒 security (вхідні дані)

## Мета
Повний REST-контракт для трекера: тонкі route handlers (parse → service → response), єдиний формат помилок, логи запитів, integration-тести.

## Ендпоінти
| Метод | Шлях | Тіло / query | Відповідь |
|---|---|---|---|
| GET | `/api/tasks` | `?status=todo\|in-progress\|done&sort=priority\|createdAt&order=asc\|desc&q=` (усе optional; default `sort=priority&order=desc`) | 200 `{ data: TaskListItem[] }` (без нотаток, з `subtaskCount`, `subtaskDone`) |
| POST | `/api/tasks` | `TaskCreateInput` | 201 `{ data: Task }` |
| GET | `/api/tasks/:id` | — | 200 `{ data: Task }` (з підзадачами й нотатками) · 404 |
| PATCH | `/api/tasks/:id` | `TaskUpdateInput` | 200 `{ data: Task }` · 400 · 404 |
| DELETE | `/api/tasks/:id` | — | 204 · 404 |
| POST | `/api/tasks/:id/subtasks` | `{ items: SubtaskCreateInput[] }` (1–6) | 201 `{ data: Subtask[] }` |
| PATCH | `/api/tasks/:id/subtasks/:subtaskId` | `{ status }` | 200 `{ data: Subtask }` |
| DELETE | `/api/tasks/:id/subtasks/:subtaskId` | — | 204 |
| POST | `/api/tasks/:id/notes` | `NoteCreateInput` | 201 `{ data: Note }` |

Підзадача, що належить іншій задачі → 404. Порожній `taskIds` — скидає фокус.

## Реалізація
1. `src/shared/api/errors.ts` (сервер): `AppError(code, status, message, details?)`; `toErrorResponse(e)` — Zod-помилка → 400 `VALIDATION_ERROR` з `details: { fieldErrors }`; `NotFoundError` → 404 `NOT_FOUND`; невідома → 500 `INTERNAL_ERROR` з загальним текстом (стек — лише в лог).
2. `src/server/http/handler.ts` — обгортка `withHandler(fn)`: try/catch → формат помилки; лог `{ method, path, status, durationMs, requestId }` на `info`; тіло запиту — лише на `debug`.
3. Query-схема `TaskListQuerySchema` (Zod, `.strict()` — невідомий параметр → 400).
4. Route handlers у `src/app/api/tasks/**/route.ts` — лише: `parse` → `taskService.*` → `NextResponse.json`. SQL у handlers немає.
5. Невалідний JSON у тілі → 400 `VALIDATION_ERROR` «Невалідний JSON».
6. Клієнтський HTTP-шар `src/shared/api/http.ts` (`fetchJson` з розбором формату помилки в `ApiError`) і `src/entities/task/api/taskApi.ts` (функції під кожен ендпоінт + query keys для TanStack Query).

## Acceptance criteria і тест-кейси
Integration-тести викликають handlers напряму (`new Request(...)`) на тимчасовій БД з seed.
- **AC-1** Створення задачі.
  - [I] валідне тіло → 201, `createdAt` = `updatedAt`, дефолти `todo`/`medium` (TC-01); без title → 400 з `details.fieldErrors.title` (TC-02); status "blocked" → 400 (TC-03); `createdAt` у тілі → 400 (TC-04); невалідний JSON → 400.
- **AC-2** Читання.
  - [I] GET list → 12 задач з `subtaskCount`; GET `/api/tasks/t1` → підзадачі й нотатки (TC-05); неіснуючий id → 404 `{error:{code:"NOT_FOUND"}}` (TC-06).
- **AC-3** Оновлення.
  - [I] PATCH status → 200, `updatedAt` змінився, `createdAt` ні (TC-07); PATCH `{}` → 400; PATCH неіснуючої → 404.
- **AC-4** Видалення.
  - [I] DELETE → 204, далі GET → 404; підзадачі зникли (TC-08); повторний DELETE → 404.
- **AC-5** Фільтр, сортування, пошук.
  - [I] `status=in-progress` → t1, t3, t9, t12 (TC-10); `sort=priority&order=desc` → усі high перед medium перед low (TC-11); `sort=createdAt&order=asc` → t10 першою (TC-12); `q=OOM` → t1; `status=foo` → 400, `sort=bar` → 400 (TC-14).
- **AC-6** Підзадачі й нотатки.
  - [I] POST 3 підзадачі `source:"ai"` з estimate → 201, `updatedAt` задачі змінився; 7 підзадач → 400; PATCH чужої підзадачі → 404; DELETE підзадачі → 204; POST нотатки "  " → 400; валідна → 201 (TC-09).
- **AC-7** Фокус.
  - [I] PUT `[t2,t7,t1]` → ранги 1–3; неіснуючий id → 404, жодних змін; 4 id → 400; дублікати → 400; `[]` → усі null.
- **AC-8** Формат помилок і логи.
  - [I] будь-яка помилка має рівно `{ error: { code, message, details? } }`; [U] `withHandler` логує status і durationMs; 500 не віддає стек клієнту.
- **AC-9** Клієнтський `fetchJson` розбирає помилку.
  - [U] відповідь 400 з форматом → `ApiError` з `code` і `fieldErrors`; мережевий збій → `ApiError` з `code: "NETWORK_ERROR"`.

## Ризики / питання
- DEV-005 додає необов’язкові параметри `page` і `pageSize` до `GET /api/tasks`. Якщо передано хоча б один, сервер повертає `{ data, pagination: { page, pageSize, total, totalPages }, summary }`. За замовчуванням сторінка 1, розмір 10, дозволений розмір 1–100. Фільтр і сортування застосовуються перед пагінацією, `total` означає кількість збігів, `summary` охоплює всі задачі. Сторінка за межами результатів зводиться до останньої доступної, а для порожнього результату повертаються `page: 1` і `totalPages: 0`. Запити без цих параметрів повертають чинний `{ data }`.
