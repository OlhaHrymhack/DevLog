# DEV-013 — README і перевірка з нуля

**Tier:** balanced (README пише sonnet) · **Залежить:** усі · **Агенти:** стандарт; E2E тут не пишемо — лише повний прогін
**Покриття ТЗ:** R-11 (що live, що mock — задокументовано), R-12, R-13, R-16 (дизайн агентів + хибні кейси), R-09 (абзац «навіщо D») · TC-60…65 з [[product]]

## Мета
Здати проєкт: README, з яким перевіряльник запускає застосунок за 2 хвилини і розуміє архітектуру й агентів; підтвердження, що clean clone працює; повний прогін тестів.

## Скоуп
**Входить:** README (усі розділи, **крім** «Рішення і компроміси»), перевірка `.env.example`, clean-clone прогін, фінальний прогін `test` + `test:e2e`, оновлення [[product]] (статус покриття R-xx).
**Не входить:** розділ «Рішення і компроміси» (пише авторка, заблоковано hook-ом — у README лишається заголовок-заглушка, створена авторкою), `AGENT_LOG.md` (авторка; агент може запропонувати список фактів окремим файлом поза репо), Loom.

## Структура README
1. **DevLog** — 2–3 речення: що це і для кого (з [[product]] §1–2).
2. **Швидкий старт:** вимоги (Node LTS версія з `engines`), `npm install && npm run dev`, `npm run db:seed` для демо-даних, відкрити `http://localhost:3000`; demo-режим без ключа; як увімкнути live (`ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`).
3. **Змінні середовища:** таблиця з `.env.example` (назва, обовʼязковість, default, призначення).
4. **Команди:** dev, build, lint, typecheck, test, test:e2e, db:seed.
5. **Архітектура:** схема шарів (FSD клієнт + DDD сервер), потік запиту `UI → TanStack Query → route handler → service → repository → SQLite`; потік агента `UI → POST /api/agents/* → runAgent ↔ модель/tools → validate → NDJSON → useAgentRun`; посилання на `docs/design/DESIGN.md`.
6. **AI-агенти** — для кожного з A, B, C, D однакова структура:
   - навіщо (1–2 речення);
   - кроки і tools (з таблиці специфікації);
   - як вирішує, що робити далі (що робить модель, що підказують детерміновані правила);
   - коли зупиняється (`submit_result`, clarify, ліміт кроків, refusal / max_tokens, «Зупинити»);
   - structured output (схема `DayPlan` / `Decomposition` / `StatusUpdate` / `Triage`);
   - валідація (Zod + factCheck → 1 повтор → fallback);
   - підтвердження користувачем (що агент **не** робить сам).
7. **Хибні кейси і як продукт їх обробляє** (≥ 2, беремо 3): A — посилання на задачу #42; B — дублікати наявних підзадач; C — згадка PR #999. Для кожного: що повернула модель → що зловила перевірка → що побачив користувач. Як відтворити: dev-панель «Зламати відповідь агента».
8. **Live і mock:** які агенти перевірені на реальному API, як працює demo (`ScriptedClient` — той самий цикл), чим demo відрізняється.
9. **Агент D — навіщо** (абзац з [[specs/DEV-012]]). Якщо D вирізано — пояснення, чому.
10. **Що свідомо не робимо** — коротко з [[product]] §3, включно з ручним додаванням підзадач і перемикачем «Серйозного режиму» в production (D-015); детальне обґрунтування — у розділі авторки.
11. **Рішення і компроміси** — заголовок без змін (пише авторка).
12. Посилання на `AGENT_LOG.md`.

## Перевірка з нуля
1. `git clone` у тимчасову теку, без `.env`, без `data/`.
2. `npm install && npm run dev` → без помилок і warning-ів у консолі; `/` відкривається; банер demo.
3. `npm run db:seed` → 12 задач; пройти вручну критичні сценарії: CRUD, фільтр, сортування, A → застосувати фокус, B → clarify на t8 → створити, C → копіювати, D → чернетка, «Зламати відповідь агента» для кожного.
4. `npm run lint && npm run typecheck && npm test && npm run test:e2e` → зелені.
5. Пошук ключа-маркера у `.next/static` після `npm run build` → 0.
6. Звірити матрицю [[product]] §4: кожна R-xx має реалізацію або пояснення у README, чому ні.
