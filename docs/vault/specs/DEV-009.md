# DEV-009 — Агент A «План на день»

**Tier:** strong · **Залежить:** DEV-005, DEV-008 · **Агенти:** стандарт + 🔒 + 🎨 + E2E + Codex
**Покриття ТЗ:** R-06 («з чого почати день, з поясненням; враховує пріоритет, вік, статус, а не перший за рангом»), R-05, R-18 · TC-30…36 з [[product]]

## Мета
Агент аналізує активні задачі й пропонує top-3 на сьогодні з поясненням кожної, плюс що свідомо відкладено. Користувач може закріпити порядок як «Фокус дня».

## Референс у прототипі
`scoreTask`, `explain`, `rulePlan`, `runPrioritize`, `renderAgentA` (592–689); `apply-A`, `apply-A-rule` (1227–1237); бейдж «Фокус #N» (965); `JOKES_A` (592–597).

## Агент (сервер, `src/server/agents/prioritize/`)
- **Вхід:** `{ debug? }` (дані агент бере сам через tools).
- **Tools (read-only):**
  - `list_active_tasks()` → задачі зі статусом ≠ done: `id, title, status, priority, ageDays, staleDays, dueInHours?, heat, openSubtasks, score` (`score` — підказка з `scoreTask`);
  - `get_task(id)` → повна задача з підзадачами й нотатками (коли моделі треба деталей для пояснення).
- **Кроки для UI:** «Зібрати активні задачі» → «Зважити пріоритет, вік, статус і дедлайни» → «Скласти порядок і пояснення» → «Перевірити відповідь (схема, існування задач)». Підписи після виконання: «Зібрав 10 активних задач», detail «Найвища вага: …», «Перевірив відповідь: 3 з 3 задач існують».
- **`submit_result` = `DayPlan`:**
  ```ts
  { items: { taskId: string; why: string /* 20–300 */; joke?: string }[] /* 1–3 */,
    deferred: { taskId: string; reason: string }[] /* 0–3 */ }
  ```
- **factCheck:** кожен `taskId` існує і не done; без дублікатів між `items` і `deferred`; якщо є задача з дедлайном < 48 год — вона в `items`; `why` згадує хоча б один фактор (пріоритет / вік / дні без змін / статус / дедлайн) — перевірка за ключовими словами.
- **`scoreTask(t, now)`** (`src/server/agents/prioritize/scoreTask.ts`): `priorityWeight×10 + min(ageDays,14)×1.2 + min(staleDays,14)×0.8 + (in-progress ? 6 : 0) + (dueAt − now < 48 год ? 30 : 0)`; вага high 3, medium 2, low 1.
- **Mock-сценарій (demo):** `list_active_tasks` → сортування за `score` → top-3, пояснення з `explain` прототипу (фрази «дедлайн менш ніж за добу», «високий пріоритет», «уже в роботі: закінчити дешевше, ніж перемикатися», «N днів без змін» / «задача свіжа, швидко дасть результат», «є готовий план з підзадач»), жарт з `JOKES_A` за рівнем температури (не в серйозному режимі — прапорець `serious` у запиті); `deferred` — до 2 задач після top-3, не high, причина «низький пріоритет» / «може почекати день».
- **Fallback `rulePlan`:** активні, сортування пріоритет ↓ → `createdAt` ↑ (старіші) → in-progress першими; top-3, **без пояснень**.
- **Хибний кейс (fault injection):** результат посилається на `taskId: "42"` → factCheck відхиляє → повтор теж з #42 → fallback. Крок 4 — `fail` «Перевірка не пройдена», detail «Відповідь посилається на задачу #42, якої немає. Повтор теж невдалий.»

## UI (`widgets/dayPlanPanel`, `features/prioritizeTasks`)
Панель «План на день» (іконка Target, тег «Агент A»), у правій колонці списку; < 1024 — згорнута картка з підсумком.
- **idle:** «Агент подивиться на всі активні задачі, зважить пріоритет, вік, статус і дедлайни та запропонує порядок на сьогодні. Нічого не змінить без вашого підтвердження.»; якщо є фокус — note-box «Фокус дня закріплено: 1. … · 2. …»; кнопка primary «✦ Скласти план на день». Підсумок (згорнута): «Пропонує, з чого почати день, і пояснює чому».
- **running:** прогрес + кроки + скелетон + «Зупинити». Підсумок «Агент працює…».
- **result:** кроки, рядок «4 кроки · 2,1 с[ · мок-відповідь]», нумерований план (номер у колі, назва-посилання на задачу, `why`, жарт кольором `--ai`), note-box «Відкладено: <назва> (низький пріоритет), …», кнопки «Застосувати порядок» (primary) + іконка «Перегенерувати план», дрібно «Це пропозиція: фокус дня зміниться лише після підтвердження.», «Відхилити» (тост). Підсумок «План готовий: 3 задачі».
- **fallback:** alert «**Відповідь агента відхилено.** Вона не пройшла перевірку двічі, тому не показуємо її.», «Порядок за простим правилом: пріоритет → вік → статус. Без пояснень від AI.», список, кнопки «Спробувати ще раз» (primary) і «Взяти цей порядок» (ghost). Підсумок «Агент не впорався, показано порядок за правилом».
- **Підтвердження:** «Застосувати порядок» → діалог «Закріпити фокус дня?», «Ці задачі отримають позначку «Фокус» у списку: 1. … 2. … 3. … Статуси й пріоритети не зміняться.», «Закріпити» → `PUT /api/tasks/focus` → бейджі «◎ Фокус #N» у списку, панель → idle з note-box, тост «🎯 Фокус дня закріплено. Тепер точно без прокрастинації» / «Фокус дня закріплено». Fallback → діалог «Закріпити порядок за правилом?».
- **Немає даних:** список не завантажився — «Агенту немає з чим працювати: список задач не завантажився.»; немає активних — «Немає активних задач для аналізу. Підозріло спокійно 🧘» (агент не запускається).

## Acceptance criteria і тест-кейси
Фіксований `now`, seed з DEV-003.
- **AC-1** `scoreTask` і порядок враховують кілька факторів.
  - [U] на seed: t2 = 78 (дедлайн +30), t1 = 47,2, t7 = 46 → top-3 t2, t1, t7 (а не t2, t7, t1 за пріоритетом і віком, як у `rulePlan`); дедлайн < 48 год дає рівно +30 (TC-32).
  - [U] синтетичний набір: medium in-progress, 7 днів без змін (40) вище за high todo, створену сьогодні (30) — порядок не дорівнює сортуванню за пріоритетом (TC-31).
- **AC-2** Mock-агент проходить цикл з tools і повертає валідний `DayPlan`.
  - [U] ScriptedClient: `list_active_tasks` → `submit_result`; результат проходить схему; кожен `why` містить фактор; done-задачі відсутні (TC-30, TC-33).
- **AC-3** factCheck.
  - [U] #42 → порушення; done-задача → порушення; дублікат між items і deferred → порушення; задача з дедлайном < 48 год поза items → порушення.
- **AC-4** Хибний кейс → fallback `rulePlan`.
  - [U] `forceInvalidOutput` → 2 спроби → fallback; `rulePlan` на seed: high за віком (t2, t7, t1); пояснень немає (TC-35).
  - [E] dev-панель «Зламати відповідь агента» → червоний alert, крок 4 з X, «Взяти цей порядок» → діалог → бейджі «Фокус #1–3».
- **AC-5** Застосування фокусу.
  - [E] «Скласти план на день» → 4 кроки → план з поясненнями → «Застосувати порядок» → діалог → «Закріпити» → у списку «Фокус #1…#3», статуси не змінились; «Скасувати» в діалозі нічого не змінює (TC-34).

  - [E] лише done-задачі → «Немає активних задач для аналізу», кнопки запуску немає (TC-36).
