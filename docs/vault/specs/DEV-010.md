# DEV-010 — Агент B «Декомпозиція»

**Tier:** strong · **Залежить:** DEV-007, DEV-008 · **Розблоковує:** DEV-012 · **Агенти:** стандарт + 🔒 + 🎨 + E2E + Codex
**Покриття ТЗ:** R-07 («структурований список підзадач за назвою й описом; за бажанням створює їх у застосунку; нечітку задачу спершу уточнює»), R-05, R-18 · TC-37…44 з [[product]]

## Мета
Агент розбиває задачу на 3–6 підзадач з оцінкою часу й поясненням. Нечітку задачу — спершу уточнює. Створює підзадачі лише ті, що користувач обрав, і лише після «Створити».

## Референс у прототипі
`TEMPLATES`, `isVague`, `pickTemplate`, `runDecompose`, `renderAgentB` (740–803); `apply-B`, `b-toggle`, `reset-B` (1253–1262, 1291); clarify submit (1310–1316); `goto-B` (1251).

## Агент (сервер, `src/server/agents/decompose/`)
- **Вхід:** `{ taskId, clarification?: string (3–1000), serious?, debug? }`.
- **Tools (read-only):**
  - `get_task(id)` → назва, опис, статус, пріоритет, наявні підзадачі (назви), нотатки;
  - `assess_clarity(id)` → `{ vague: boolean, reasons: string[] }` за `isVague` (опис < 40 символів або «щось / якось / покращити / розібратись / погані» у назві чи описі) — підказка; рішення приймає модель, але при `vague: true` і без `clarification` має повернути clarify.
- **Кроки для UI:** «Прочитати назву, опис і наявні підзадачі» (detail «2 підзадачі вже є») → «Оцінити чіткість формулювання» («Задача нечітка: потрібне уточнення» / «Формулювання чітке» / «Уточнення отримано, контексту достатньо») → «Згенерувати підзадачі» (detail «5 пунктів») → «Перевірити структуру (3–6 пунктів, без дублів)» («Структуру перевірено»).
- **`submit_result` = `Decomposition`** (discriminated union):
  ```ts
  | { kind: "clarify"; questions: string[] /* 1–3 */ }
  | { kind: "subtasks"; items: { title: string /* 3–120 */; estimate: string /* «~2 год» */; rationale: string /* 3–160 */ }[] /* 3–6 */ }
  ```
- **factCheck:** для `subtasks` — немає дублікатів між собою і з наявними підзадачами (нормалізоване порівняння: lowercase, без пунктуації, збіг перших 12 символів або вкладення); кількість 3–6 після цього; `clarify` заборонений, якщо `clarification` вже дано.
- **Mock-сценарій:** `get_task` → `assess_clarity` → якщо vague і немає уточнення → `clarify` з двома питаннями прототипу («Що саме не так: падають, повільні чи їх немає?», «Які тести: unit, e2e чи всі? Є приклад падіння?») — для задач про тести; для інших — загальні («Який результат вважатимемо готовим?», «Що вже відомо або спробувано?»); інакше шаблон за `pickTemplate` (tests / bug / upgrade / api / generic — рядки 743–758) з урахуванням уточнення, мінус наявні підзадачі.
- **Fallback:** шаблон `generic` («Уточнити критерії готовності ~30 хв», «Розбити реалізацію на етапи ~1 год», «Реалізувати перший етап ~3 год», «Перевірити й задокументувати ~1 год»).
- **Хибний кейс (fault injection):** результат містить дублікати наявних підзадач → після відкидання < 3 → порушення → повтор теж → fallback. Крок 4 — `fail` «Структура не пройшла перевірку», detail «Дублікати з наявними підзадачами».

## UI (`widgets/decomposePanel`, `features/decomposeTask`)
Панель «Декомпозиція» (ListTree, тег «Агент B»), права колонка деталей / вкладка «Підзадачі».
- **idle:** «Агент розіб'є задачу на 3–6 підзадач з оцінкою часу. Якщо задача нечітка, спершу поставить уточнювальні питання. Підзадачі з'являться лише після підтвердження.»; якщо `isVague` — alert-info «Опис короткий: агент, найімовірніше, попросить уточнення.» (`isVague` дублюється в `entities/task/model` як чиста функція для цієї підказки й форми); кнопка «Розбити на підзадачі».
- **running:** прогрес, кроки, «Зупинити».
- **clarify:** бульбашка «🤔 Опису замало, щоб розбити задачу. Уточніть, будь ласка: 1. … 2. …»; форма «Ваша відповідь», placeholder «Наприклад: e2e checkout, падає ~1 з 8 запусків у CI»; < 3 символів → «Напишіть хоча б кілька слів»; «Відповісти і продовжити» → **спершу** `POST /notes` з текстом «Уточнення для декомпозиції: <відповідь>», потім новий запуск з `clarification`; «Скасувати» → idle; дрібно «Підзадачі не генеруються, доки немає відповіді.»
- **result / fallback:** (fallback — alert «**Відповідь агента відхилено.** Пропонуємо базовий шаблон без AI. Його можна відредагувати після створення.») «Пропоновані підзадачі»: чекбокс (усі увімкнені), назва, «~2 год · пояснення»; кнопка «Створити N підзадач» (N і відмінок оновлюються; disabled при 0), «Скасувати»; дрібно «Нічого не створено, доки ви не натиснете «Створити».»
- **Підтвердження:** «Створити N» → `POST /api/tasks/:id/subtasks` з обраними (`source: "ai"`, `estimate`, `rationale`) → список підзадач оновлено з бейджем «AI», тост «Створено 4 підзадачі», панель → **applied**: alert-info «Створено 4 підзадачі. План є, тепер лишилось його виконати 😅» + «Розбити ще раз».
- Запуск з «Розбити з AI» (порожній список підзадач) і з агента D (`?tab=decompose&autorun=1`) — одразу `start()`.

## Acceptance criteria і тест-кейси
- **AC-1** Чітка задача → 3–6 підзадач з оцінкою і поясненням.
  - [U] mock на t7 (upgrade) → 5 пунктів шаблону upgrade, кожен з `estimate` і `rationale` (TC-37).
  - [E] t7 → «Розбити на підзадачі» → 4 кроки → 5 пунктів з чекбоксами.
- **AC-2** Нечітка задача → clarify, без генерації.
  - [U] t8 («Зробити щось з тестами», «Тести погані.») → `kind: "clarify"`, 2 питання; крок «Згенерувати» не виконувався (TC-38).
  - [E] t8 → alert «Опис короткий…» в idle → запуск → питання і форма.
- **AC-3** Уточнення зберігається нотаткою і продовжує генерацію.
  - [E] відповідь «e2e checkout, падає 1 з 8 у CI» → у нотатках «Уточнення для декомпозиції: …» → шаблон tests (4 пункти) (TC-39); [U] `clarify` при наявному `clarification` → порушення factCheck.
- **AC-4** Нічого не створюється без підтвердження; створюються лише обрані.
  - [E] після результату кількість підзадач у задачі не змінилась (TC-40); зняти 1 з 5 → кнопка «Створити 4 підзадачі» → створено рівно 4 з бейджем «AI» (TC-41); зняти всі → кнопка disabled.
- **AC-5** Дублікати відкидаються.
  - [U] factCheck на t1 (наявні «Відтворити витік на staging», «Зняти heap snapshot до і після 2 год роботи»): пункт «Зняти heap snapshot» → дублікат (вкладення); «Відтворити проблему стабільно» → не дублікат (перші 12 символів різні); два однакові пункти в результаті → дублікат (TC-42).
  - [U] 1 або 10 пунктів → порушення схеми (TC-43).
- **AC-6** Хибний кейс → fallback generic.
  - [U] `forceInvalidOutput` → 2 спроби з дублікатами → fallback з 4 пунктами generic.
  - [E] dev-панель → alert «Відповідь агента відхилено», шаблон, «Створити 4 підзадачі» працює.
- **AC-7** Скасування і стоп.
  - [E] «Скасувати» в результаті / clarify → idle, нічого не створено (TC-44); «Зупинити» → idle.
- **AC-8** Автозапуск.
  - [E] `/tasks/t3?tab=decompose&autorun=1` → вкладка «Підзадачі», агент уже працює; «Розбити з AI» в порожньому списку підзадач → те саме.
- **AC-9** Applied.
  - [E] після створення — «Створено N підзадач…» і «Розбити ще раз»; повторний запуск не пропонує вже створені пункти.
