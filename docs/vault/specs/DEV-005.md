# DEV-005 — Список задач

**Tier:** balanced · **Залежить:** DEV-002, DEV-004 · **Розблоковує:** DEV-006, DEV-009, DEV-012 · **Агенти:** стандарт + 🎨 + E2E (фільтр + сортування)
**Покриття ТЗ:** R-02 (список, фільтр за статусом, сортування за пріоритетом / датою), R-19 · TC-10…16, TC-70, TC-72 з [[product]]

## Мета
Головний екран: шапка, тулбар, список задач з реальних даних у трьох розкладках, усі стани екрана, місця під агентів A і D у правій колонці.

## Референс у прототипі
`renderShell` (1057–1070), `renderBanner` (1076–1079), `renderList` (924–949), `renderFilters` (950–960), `taskRow` (961–972), `renderTasks` (973–993), `filteredSorted` (914–923), `openLegend` (1167–1172), `openStates` (1173–1185), клавіші (1318–1333), CSS 87–164.

## Скоуп
**Входить:** AppHeader, DemoModeBanner, сторінка `/`, тулбар (пошук, фільтр, сортування, «Температура»), TaskList, усі стани, HeatLegendDialog, гарячі клавіші, «Серйозний режим», dev-панель «Стани прототипу», FAB, skip-link, порожні контейнери під агентів A/D (`aside`, наповнення — DEV-009/012).
**Не входить:** діалоги створення / редагування / видалення (DEV-006 — кнопки є, відкривають діалоги з DEV-006; до того — no-op disabled), агенти.

## Реалізація
1. `src/app/layout.tsx`: провайдери (TanStack Query, тема, `Toaster` sonner з `aria-live`), skip-link «Перейти до вмісту» → `#main`, `widgets/appHeader`, `widgets/demoModeBanner`, `<main id="main" tabIndex={-1}>`.
2. **AppHeader:** лого `dl` + «DEVLOG» → `/`, «/ Platform team» (ховається < 768), кнопка «Стани прототипу» (іконка колби, лише dev), ThemeToggle, «Нова задача» primary (ховається < 768 → FAB 56×56 справа знизу; на сторінці задачі FAB немає).
3. **DemoModeBanner** (лише `aiMode === "demo"`): іконка WifiOff, «**Демо-режим AI.** OPENAI_API_KEY не задано в .env, тому агенти повертають детерміновані мок-відповіді. Додайте ключ і перезапустіть `npm run dev`.» `role="status"`.
4. **views/tasksList** — сітка: `head` (h1 «Задачі» + рядок мети) / `main` / `aside` 384px sticky ≥ 1024; < 1024 — aside над списком 2 колонки; < 768 — 1 колонка.
5. **Рядок мети:** «12 задач · 4 в роботі · 3 гарячі 🌶️» (гарячі = rank ≥ 2; емодзі прибирається в серйозному режимі); стани: «Завантаження…», «Не вдалося завантажити», «0 задач».
6. **Тулбар:**
   - `features/taskSearch` — поле «Пошук задач…», `kbd /` (ховається < 768); пошук по назві + опису; debounce 200 мс; передається як `q`.
   - `features/taskFilter` — сегмент «Всі · До роботи · В роботі · Готово» з лічильниками, `aria-pressed`; < 768 гортається вбік.
   - `features/taskSort` — select: «Пріоритет: високий → низький» (default), «Пріоритет: низький → високий», «Дата: спершу нові», «Дата: спершу старі».
   - кнопка «Температура» (іконка HelpCircle; < 768 лише іконка) → `features/heatLegend` HeatLegendDialog.
   - Стан фільтра / сортування / пошуку — `useTaskListParams` (локальний стан сторінки); лічильники рахуються з повного списку без фільтра.
7. **Дані:** `useTaskPage(params)` (TanStack Query) → `GET /api/tasks?page=…&pageSize=10`. API повертає відфільтровану й відсортовану сторінку та глобальні лічильники. Зміни пошуку, статусу й сортування повертають на першу сторінку. Навігація з’являється, коли результат розбитий на кілька сторінок.
8. **TaskList** (`widgets/taskList`): таблиця з заголовками «Задача · Статус · Пріоритет · Вік · 🌶️ · дії» ≥ 1024, картки < 1024. Рядок: назва-посилання на `/tasks/[id]` (весь рядок клікабельний, фокус підсвічує рядок), бейдж «Фокус #N» якщо `focusRank`, опис в 1 рядок (картка — 2), StatusBadge, PriorityLabel, «Вік» = `ageLabel(createdAt)` з `title` «Створено <дата>», червоний при rank ≥ 2, HeatBadge (лише 🌶️+), кнопки «Редагувати «…»» / «Видалити «…»».
9. **Стани** (`TaskListSkeleton`, `EmptyState`):
   - loading — 6 скелетон-рядків, `aria-busy`;
   - error — 🔌 «Не вдалося завантажити задачі», «Сервер не відповів (GET /api/tasks → 500).» + жарт «Найімовірніше, хтось знову перезапустив воркер 🙃», кнопка «Спробувати ще раз» (refetch, тост «Задачі завантажено»);
   - empty — 🧘 «Нічого не горить» / «Або все під контролем, або ти забув створити задачі. Створи першу, агенти підхоплять.» + «Нова задача»; серйозно: 📋 «Поки що задач немає» / «Створіть першу задачу, і агенти допоможуть з пріоритетами та підзадачами.»;
   - нічого за фільтром — «Немає задач зі статусом «В роботі»» або «Нічого не знайдено за запитом «…»» + «Скинути фільтри» (скидає і фільтр, і пошук).
10. **HeatLegendDialog** (wide 760): таблиця 7 рівнів (емодзі · рівень + правило · розшифровка · підпис), вступ «Рахується за пріоритетом, днями без змін (статус, підзадачі, нотатки) і дедлайном. У списку показуються лише 🌶️ і вище, щоб погляд чіплявся за проблеми.», кнопка «Зрозуміло». Колонка «Підпис» — лише не в серйозному режимі.
11. **Серйозний режим** (D-015): `features/seriousMode` — контекст `useSerious()`; `copy.uk.ts` — пари `{ serious, funny }`, хелпер `t(key)`. **Перемикач лише в dev-панелі** (стан у `localStorage["devlog-serious"]`); у production перемикача немає, `useSerious()` завжди `false`, localStorage не читається — гумор у мікрокопі ввімкнений. Правило DESIGN §1.4 діє без перемикача: у помилках, діалозі видалення й апдейтах для менеджера гумору немає ніколи.
12. **Dev-панель «Стани прототипу»** (`widgets/devStatesPanel`, лише `NODE_ENV !== "production"`): «Дані екрана» (Дані / Завантаження / Порожньо / Помилка — примусово перевизначає стан запиту), «Режим AI» (Реальний API / Демо без ключа — лише візуально, для банера й тегів), «Зламати відповідь агента» (зберігається в контексті, DEV-008 передає в запити агентів), «Серйозний режим», підказка «Клавіші: / пошук · N нова задача · Esc закрити вікно», «Готово».
13. **Гарячі клавіші** (`shared/lib/useHotkeys`): `/` — фокус у пошук; `N`, `n`, `Т`, `т` — нова задача; `Esc` — закрити діалог. Не спрацьовують, коли фокус в input / textarea / select, відкрито діалог або натиснуто Ctrl / Cmd / Alt.

## Acceptance criteria і тест-кейси
- **AC-1** Список показує задачі з API у правильному порядку за замовчуванням.
  - [E] seed → 12 рядків, перші чотири — high у порядку createdAt desc: t9, t1, t7, t2; рядок мети «12 задач · 4 в роботі · 3 гарячі» (t1 hot, t7 fire, t2 alarm).
- **AC-2** Фільтр за статусом з лічильниками.
  - [E] «В роботі» → 4 рядки, `aria-pressed=true`; лічильники «Всі 12 · До роботи 6 · В роботі 4 · Готово 2» не змінюються від фільтра (TC-10).
- **AC-3** Сортування.
  - [U] `useTaskListParams` мапить опції select на `sort/order`; [E] «Дата: спершу старі» → першою t10; «Пріоритет: низький → високий» → спершу low (TC-11, TC-12).
- **AC-4** Пошук + фільтр + сортування комбінуються.
  - [E] «В роботі» + пошук «логування» → лише t12; «Скинути фільтри» повертає 12 (TC-13).
- **AC-5** Стани екрана.
  - [E] мок 500 (`page.route`) → error + retry, після retry → список (TC-16); порожня БД → empty з CTA (TC-15); фільтр без збігів → «Немає задач зі статусом…» + «Скинути фільтри»; повільна відповідь → скелетон з `aria-busy`.
- **AC-6** Температура.
  - [U] TaskRow не рендерить HeatBadge для fresh/calm/done; [E] у t2 — 🏚️🔥🚒 з tooltip по фокусу; «Температура» відкриває легенду з 7 рядками, Esc закриває, фокус повертається на кнопку.
- **AC-7** Адаптив.
  - [E] 1280 → таблиця з заголовками; 768 → картки у 2 колонки; 375 → 1 колонка, FAB видно, «Нова задача» в шапці приховано, без горизонтального скролу (`scrollWidth <= clientWidth`) (TC-70).
- **AC-8** Демо-банер.
  - [E] `AI_MODE=demo` → банер з текстом про OPENAI_API_KEY; [U] з `aiMode=live` банера немає.
- **AC-9** Гарячі клавіші.
  - [E] `/` фокусує пошук; `Т` (кирилиця) відкриває діалог «Нова задача» (після DEV-006; до того — подія `onNewTask` викликана); у фокусі пошуку `N` друкує літеру, а не відкриває діалог.
- **AC-10** Серйозний режим.
  - [U] `t(key)` повертає серйозний варіант при `serious=true`; [E] (dev) увімкнути в dev-панелі → empty-стан «Поки що задач немає», у рядку мети немає 🌶️, у легенді немає колонки «Підпис»; reload → режим збережено.
  - [U] у production: перемикача немає ні в шапці, ні деінде; `useSerious()` = `false` навіть з `devlog-serious=true` у localStorage.
- **AC-11** Dev-панель лише в dev.
  - [U] у production кнопки колби немає; [E] у dev «Дані екрана → Помилка» показує error-стан.
- **AC-12** Доступність.
  - [E] skip-link першим по Tab, переводить фокус на `main`; усі кнопки-іконки мають `aria-label`; фільтр — `role="group"` з `aria-label` «Фільтр за статусом» (TC-72).

- **AC-13** Серверна пагінація.
  - [I] `page=1` і `page=2` повертають відповідно 10 і 2 записи демо-набору, без повторів. Фільтр і пошук застосовуються до всіх задач. Невалідна сторінка або розмір → 400.
  - [E] «Далі» запитує наступну сторінку з сервера, «Назад» повертає першу. Зміни фільтра скидають сторінку, а глобальні лічильники зберігаються.
