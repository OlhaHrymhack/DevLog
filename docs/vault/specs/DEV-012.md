# DEV-012 — Агент D «Радар застряглих»

**Tier:** strong · **Залежить:** DEV-008, DEV-010 · **Агенти:** стандарт + 🔒 + 🎨 + E2E + Codex
**Покриття ТЗ:** R-09 (власна агентна функція + абзац, навіщо вона команді), R-05, R-18 · TC-52…57 з [[product]]
**Перша кандидатка на вирізання** при нестачі часу (див. [[product]] §3) — тоді в README пояснюємо чому.

## Мета
Агент знаходить задачі «в роботі», що давно не рухаються, ставить кожній діагноз і пропонує одну конкретну дію: чернетку запиту на ревʼю, декомпозицію через агента B або прохання про допомогу.

## Навіщо (для README, абзац «навіщо D»)
Застряглі задачі найдорожчі, бо їх ніхто не бачить, поки не стало пізно. Агент A каже, що робити сьогодні, але не каже, чому щось стоїть тиждень. D дивиться на історію (дні без змін, нотатки, підзадачі), називає ймовірну причину і знімає найнеприємнішу частину — написати колезі «глянь, будь ласка».

## Референс у прототипі
`diagnose`, `runRadar`, `renderAgentD` (691–738); `d-snooze`, `d-act` (1238–1249).

## Агент (сервер, `src/server/agents/stuckRadar/`)
- **Вхід:** `{ snoozedIds: string[], serious?, debug? }`.
- **Tools (read-only):**
  - `find_stale_tasks({ minDays: 3 })` → in-progress задачі з ≥ 3 днями без змін, крім `snoozedIds`: `id, title, staleDays, openSubtasks, subtaskCount, noteCount`;
  - `get_task_context(id)` → підзадачі й нотатки;
  - `diagnose_hint(id)` → правило прототипу як підказка.
- **Правило `diagnose`** (порядок важливий):
  1. нотатки містять `PR`, `ревʼю` або `review` (регістр не важливий) → «Чекає на ревʼю» — «У нотатці згадано PR, який чекає ревʼю. Блокер поза автором задачі.» → дія `draft-review` «Чернетка запиту на ревʼю»;
  2. 0 підзадач і 0 нотаток → «Задача розмита» — «Немає ні підзадач, ні нотаток: незрозуміло, з чого почати.» → `split` «Розбити на підзадачі»;
  3. ≥ 3 відкритих підзадач → «Задача завелика» — «N відкритих підзадач і жодного руху. Варто попросити допомоги або зменшити обсяг.» → `draft-help` «Чернетка прохання про допомогу»;
  4. інакше → «Немає активності» — «Задача давно не оновлювалась.» → `open` «Відкрити задачу».
  Жарти (лише не в серйозному режимі): «PR чекає ревʼю. Ревʼюер, мабуть, теж чекає, поки його хтось пінгане ⏳»; «"В роботі" N днів без жодної нотатки. Або ти геній, або вона тебе перемогла 🕸️»; «Класична пастка "та там на 5 хвилин" 🫠».
- **Кроки для UI:** «Знайти задачі «в роботі» без змін понад 3 дні» («Знайшов 3 застряглі задачі») → «Зіставити з нотатками та підзадачами» → «Визначити ймовірну причину» (detail — перелік причин) → «Запропонувати конкретну дію». 0 знайдено → зупинка після кроку 2 з порожнім результатом.
- **`submit_result` = `Triage`:** `{ items: { taskId, cause: "waiting-review"|"vague"|"too-big"|"no-activity", why: string, action: "draft-review"|"split"|"draft-help"|"open", draft?: string /* для draft-* : 20–500 */ }[] }`.
- **factCheck:** кожен `taskId` — серед знайдених `find_stale_tasks` (in-progress, не snoozed); `action` відповідає `cause`; у `draft` для `waiting-review` згадано PR, що є в нотатках (або просто «PR», якщо номера немає); немає PR-номерів, яких немає в нотатках.
- **Чернетки (mock):**
  - ревʼю: «Привіт! Можеш глянути PR #318 по задачі «<назва>»? Він блокує реліз фіксу, ревʼю займе ~15 хв. Дякую 🙏»;
  - допомога: «Привіт! Задача «<назва>» вийшла більшою, ніж здавалось: N відкритих підзадач. Хтось може взяти одну з них? Деталі в DevLog.»
- **Fallback:** ті самі знайдені задачі, усі з дією `open`, без порад і жартів.
- **Хибний кейс (fault injection):** дія для задачі, якої немає серед знайдених → порушення → повтор теж → fallback. Крок 4 — `fail` «Дії не пройшли перевірку», detail «Агент запропонував змінити задачу, якої немає».

## UI (`widgets/stuckRadarPanel`, `features/detectStuckTasks`)
Панель «Радар застряглих» (іконка Radar, тег «Агент D») під панеллю A; < 1024 — згорнута з підсумком.
- **idle:** «Агент знаходить задачі, які давно не рухаються, з'ясовує ймовірну причину (розмита, завелика, чекає ревʼю) і пропонує дію.» + кнопка `ai` «Просканувати». Підсумок «Шукає задачі, що застрягли «в роботі»».
- **running:** прогрес, кроки, «Зупинити». Підсумок «Сканую…».
- **result:** кроки; картка на кожну задачу: назва-посилання, «5 днів без змін» (колір heat), «**Чекає на ревʼю.** <why>», жарт (`--ai`), кнопки «<дія>» (primary sm) і «Ігнорувати» (ghost sm); внизу «Сканувати ще раз». Підсумок «Знайдено застряглих: 3». Порожньо — 🧘 «Нічого не застрягло. Або все під контролем, або ти забув оновити статуси.» / «Застряглих задач немає.»
- **fallback:** alert «**Пропозиції агента відхилено.** Показую лише знайдені задачі без порад.» + картки з «Відкрити задачу».
- **Дії:**
  - `draft-review` / `draft-help` → `DraftMessageDialog` «Чернетка запиту на ревʼю» / «Чернетка прохання про допомогу»: бульбашка з текстом, «Агент нічого не надсилає сам. Скопіюйте й вставте в Slack.», «Закрити», «Скопіювати» (тост «Чернетку скопійовано»), «Відхилити» (тост «Чернетку відхилено», діалог закрито);
  - `split` → перехід на `/tasks/<id>?tab=decompose&autorun=1` (агент B стартує сам);
  - `open` → `/tasks/<id>`;
  - «Ігнорувати» → id у `snoozedIds` (стан сесії на клієнті), картка зникає, тост «🙈 Окей, вдаємо, що її не існує» / «Сховано до наступного сканування». Повторне сканування в межах сесії її не показує; після перезавантаження сторінки — знову показує.
- Картки, задачі яких уже не in-progress (змінили статус), ховаються з результату без повторного сканування.
