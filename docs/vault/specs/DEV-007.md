# DEV-007 — Деталі задачі

**Tier:** balanced · **Залежить:** DEV-006 · **Розблоковує:** DEV-010, DEV-011 · **Агенти:** стандарт + 🎨 + E2E (підзадачі + нотатки)
**Покриття ТЗ:** R-01 (перегляд), R-07/R-08 (дані для агентів B і C: підзадачі, нотатки) · TC-05, TC-06, TC-09 з [[product]]

## Мета
Сторінка задачі `/tasks/[id]`: перегляд і швидка зміна статусу / пріоритету, підзадачі з прогресом, нотатки про виконання. Права колонка — місце під агентів B і C (наповнення — DEV-010/011).

## Референс у прототипі
`renderDetail` (998–1021), `renderDetailMain` (1022–1052), обробники `set-status` / `set-priority` (1278–1284), `toggle-sub` (1285–1290), `del-sub` (1295–1298), `note` submit (1304–1309), вкладки (1250), CSS 248–284.

## Реалізація
1. `src/app/tasks/[id]/page.tsx` → `views/taskDetails`. Дані — `useTask(id)` (`GET /api/tasks/:id`).
2. Розклад: ≥ 1024 — 2 колонки (`main` + `side` 440px); < 1024 — вкладки `role="tablist"` sticky під шапкою: «Задача» (FileText) · «Підзадачі» (ListTree, агент B) · «Апдейт» (MessageSquare, агент C); < 420 — без іконок. Активна вкладка — `?tab=task|decompose|update` (потрібно для переходу з агента D з автозапуском). Перехід на іншу задачу скидає вкладку на «Задача».
3. «← Задачі» — посилання на `/`.
4. **TaskOverview** (`widgets/taskOverview`): h1 назва (34px, < 768 — 26px, перенос довгих слів); кнопки «Редагувати» (ghost sm) і «Видалити» (danger-ghost sm) — діалоги з DEV-006; мета-рядок:
   - `features/taskStatusChange` `StatusSelect` — pill у кольорі статусу; зміна → PATCH, тост «Статус: В роботі»; гаряча → done → «🧯 Пожежу загашено…» / «Задачу закрито»;
   - `PrioritySelect` — «Високий пріоритет» тощо; тост «Пріоритет: Високий»;
   - HeatBadge (`always`) + назва рівня; «Створено <дата> · <вік>»; якщо є `dueAt` — «· **дедлайн <дата>**» (колір priority-high).
   - Картка «Опис».
5. **SubtaskList** (`widgets/subtaskList`): заголовок «Підзадачі» + «N з M готово»; прогрес-бар (колір success, `aria-label` «Прогрес підзадач»); рядок: чекбокс (`aria-label` = назва; зона кліку 32px) → PATCH todo ↔ done, закреслення для done; бейдж «✦ AI» для `source: ai`; кнопка X «Видалити підзадачу «…»» → DELETE без підтвердження, тост «Підзадачу видалено».
   - Коли всі підзадачі done, а задача ні → тост «🏁 Усі підзадачі готові. Закрий задачу, поки вона не передумала» / «Усі підзадачі готові. Можна закривати задачу».
   - Порожньо: «Підзадач ще немає. Агент декомпозиції запропонує план, а ви вирішите, що створити.» + кнопка `ai` «Розбити з AI» → вкладка «Підзадачі» + запуск агента B (до DEV-010 кнопка лише перемикає вкладку).
6. **NoteList** (`widgets/noteList`) + `features/noteAdd` `AddNoteForm`: заголовок «Нотатки про виконання»; нотатка — текст + «сьогодні» / «3 дні тому»; порожньо — «Нотаток немає. Агент статус-апдейту пише точніше, коли вони є.»; форма «Нова нотатка», placeholder «Що зроблено, що блокує, посилання на PR…», кнопка «Додати нотатку»; порожня → «Нотатка порожня», фокус у поле; успіх → тост «Нотатку додано», поле очищено.
7. Стани: loading — скелетон заголовка, мети й опису (`aria-busy`); 404 — 🕳️ «Задачу не знайдено», «Можливо, її видалили. Ніхто й не помітить 🪦» (серйозно — без жарту) + «До списку»; 500 — 🔌 «Не вдалося завантажити задачу», «GET /api/tasks/<id> → 500» + «Спробувати ще раз».
8. Мутації — invalidate `["task", id]` і `["tasks"]`, щоб список і температура оновились.

## Acceptance criteria і тест-кейси
- **AC-1** Перегляд задачі.
  - [E] клік по t1 у списку → `/tasks/t1`: назва, «В роботі», «Високий пріоритет», 🌶️🌶️ «Гаряча», опис, 2 підзадачі «2 з 2 готово», 1 нотатка (TC-05).
- **AC-2** Зміна статусу і пріоритету з деталей.
  - [E] StatusSelect → «Готово» → тост; повернення в список → у t1 бейдж «Готово», рядок закреслено.
- **AC-3** Підзадачі.
  - [E] t9: зняти / поставити чекбокс → лічильник і прогрес оновились; поставити всі → тост «Усі підзадачі готові…»; видалити підзадачу → зникла, тост (TC-09).
  - [U] прогрес = round(done / all × 100); бейдж «AI» лише для `source: ai`.
- **AC-4** Нотатки.
  - [E] порожня → «Нотатка порожня» і фокус; валідна → з'явилась зверху/знизу списку з «сьогодні», тост; температура задачі стала 🥒 (updatedAt оновився).
- **AC-5** Не знайдено і помилка.
  - [E] `/tasks/nope` → «Задачу не знайдено» + «До списку» (TC-06); мок 500 → error + retry.
- **AC-6** Вкладки на tablet / mobile.
  - [E] 768 → видно вкладки, за замовчуванням «Задача»; «Підзадачі» → видно лише панель агента B; `?tab=decompose` відкриває одразу вкладку «Підзадачі»; стрілки / Tab по вкладках з `aria-selected`.
- **AC-7** Видалення з деталей.
  - [E] «Видалити» → підтвердження → перехід на `/`, тост.

## Відкриті питання
1. **Ручне додавання підзадачі.** У прототипі його немає: підзадачі створює лише агент B після підтвердження; користувач може перемкнути й видалити. ТЗ цього не вимагає. Пропоную **не додавати** (KISS) і пояснити в README. Якщо потрібне — +1 поле «Додати підзадачу» під списком.
