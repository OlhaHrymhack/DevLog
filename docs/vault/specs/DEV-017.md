# DEV-017 — підготовка DevLog до здачі

Мета — дати перевіряльникам публічне посилання на DevLog і два відтворювані способи запуску локально. Vercel використовує окрему базу з демонстраційними даними.

## Критерії приймання

1. **AC-1 — README.** Є перевірені команди запуску з чистого клону через npm і Docker, адреса застосунку, налаштування демо й live, опис спільної квоти та посилання на перевірений публічний деплой. Окремий короткий розділ пояснює, як задачі проходять Factory від Discovery до PR і ретро, як працює цикл виправлень, що перевіряють автоматичні перевірки та де рішення залишається за людиною. Описано межі MVP і фактичні компроміси, зокрема відсутність входу й розділення доступу та локальну SQLite у початковій версії. Авторський розділ «Рішення і компроміси» і `AGENT_LOG.md` поза цією задачею.
2. **AC-2 — Docker.** Локально застосунок стартує за інструкцією в demo без ключа. Health та основні маршрути працюють. SQLite і зміни задач зберігаються в іменованому томі після повторного створення контейнера. Секрети та локальна БД не входять у build context чи образ.
3. **AC-3 — Vercel і дані.** Публічний застосунок працює з окремою довговічною SQLite-сумісною базою. Міграції й повторний деплой зберігають задачі та квоти. Локальний запуск відкриває наявні SQLite-файли. Пошук українською без урахування регістру, транзакції, CRUD і стрім агентів проходять регресійні перевірки.
4. **AC-4 — квота.** Кожен агент, доступний у релізі, має 10 запусків на всіх відвідувачів Vercel Production разом, без автоматичного скидання. Сервер атомарно резервує спробу перед запуском моделі. Паралельні запити й різні інстанси бюджету не перевищують. Невалідний запит до резервування нічого не витрачає. Скасування або помилка після резервування не повертає спробу.
5. **AC-5 — відмова та контроль витрат.** Після 10 спроб маршрут повертає 429 з повідомленням у UI. При недоступній квоті модель не викликається, а UI отримує 503. Кожен агент має окремий лічильник. Production smoke не дає обійти квоту. Preview не використовує production-ключ і production-базу. Ліміти кроків і вихідних токенів залишаються активними.
6. **AC-6 — гігієна.** Перевірено відстежувані скріншоти, архіви й згенеровані файли. Прибираються лише підтверджені зайві артефакти. Збірка та публічний застосунок не включають локальні дані, секрети, тестові звіти чи службові документи.
7. **AC-7 — публічний запуск.** Після рев’ю та merge перевірити в браузері доступ без входу у Vercel, відображення синтетичних задач, CRUD і поведінку агентів. Межу 10/11 перевірити з підміненою моделлю або на ізольованому demo Preview, щоб залишити публічну квоту відвідувачам. Production URL передати користувачці після перевірки.

## Уточнення до AC-1

У розділі README про Factory коротко описати два етапи, які вирішили не додавати в невеликому DevLog:

- **Окрема роль для прибирання.** У більших репозиторіях вона могла б регулярно знаходити застарілі файли, тимчасові артефакти й невикористані залежності та пропонувати їх видалення на рев’ю.
- **Аналіз помилок і автоматичні виправлення.** Factory уже розпізнає повторні провали перевірок і повертає задачу розробнику. У більшому проєкті окремий механізм міг би групувати повторювані помилки, виявляти їхні причини й готувати виправлення для повторної перевірки та рев’ю.
