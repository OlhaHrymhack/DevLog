# 2026-11-22 — у staged-змінах лишився `@anthropic-ai/sdk`; guard блокував heredoc з `${KEY_MARKER}`

- **Що сталося:**
  1. На старті реалізації в `package.json` / `package-lock.json` (staged) уже була залежність `@anthropic-ai/sdk`, хоча погоджений план DEV-008 після рішення користувачки вимагає `openai`.
  2. Дві Bash-команди developer-а заблокував PreToolUse guard «доступ до секретів заборонений»: (а) `grep -rn` для пошуку згадок `ANTHROPIC` (рекурсивний grep заборонений правилом); (б) heredoc, що дописував у тест рядок із шаблоном `` `Bearer ${KEY_MARKER}` `` і назвою `OPENAI_API_KEY` — guard сприйняв це як вивід env-змінної.
- **Причина:**
  1. Залежність додали до зміни рішення про SDK; staged-стан не оновили разом із планом.
  2. (а) — коректне блокування за правилом; (б) — хибнопозитивне спрацювання на `${..._KEY...}` у тексті команди, хоча це JS-шаблон у тестовому файлі, а не shell-змінна.
- **Як виявили:** git status на старті задачі; повідомлення guard-а (записані в `.factory/guard-log.jsonl`).
- **Як виправили:** `npm uninstall @anthropic-ai/sdk` і `npm install openai@^7.62.0` (lock оновлено npm). Пошук — через `rg` (поважає .gitignore). Тест логера дописано через Edit tool, ключ у рядку складається з частин (`["Bearer", KEY_MARKER].join(" ")`). Обходу guard-а не було.
- **Як запобігти повторенню:** при зміні рішення щодо залежності в плані одразу синхронізувати `package.json`/lock; тестові фікстури з ключами писати через Edit/Write, не через heredoc у Bash.
- Пов'язано: [[specs/DEV-008]]
