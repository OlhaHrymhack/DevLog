# 2026-11-21 — CI: guard дозволяв `rm -rf` усередині проєкту, якщо проєкт лежить у tmp

- **Що сталося:** PR #1, job `factory-selftest` у GitHub Actions: 72/73, впав сценарій «rm -rf src → deny». Локально на macOS — зелено.
- **Причина:** правило вважало безпечною будь-яку ціль у `os.tmpdir()`. На Linux tmpdir = `/tmp`, і selftest-проєкт сам лежить у `/tmp` → `rm -rf src` проєкту виглядав як «tmp». На macOS tmpdir — `/var/folders/...`, тому локально не відтворювалось; також не враховувався symlink `/var` → `/private/var`.
- **Як виявили:** CI на першому PR.
- **Як виправили:** ціль безпечна лише якщо вона строго всередині tmpdir **і не всередині проєкту**, з realpath найближчого існуючого предка. Відтворено локально через `TMPDIR=<папка> selftest` (без фіксу 72/73, з фіксом 73/73).
- **Як запобігти:** CI на Linux — обов'язковий gate; для platform-залежної логіки — сценарій з підміною `TMPDIR`.
- Примітка: зміну в робочому дереві знайдено незакоміченою на `stage` (автор — не основна сесія); перенесено в PR #1 після перевірки.
