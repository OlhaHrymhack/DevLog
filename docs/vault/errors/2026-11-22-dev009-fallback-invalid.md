# 2026-11-22 — fallback-план давав `FALLBACK_INVALID`

## 1. Fallback без термінових задач
- **Що сталося:** `rulePlan` за порядком зі спеки (пріоритет → вік → статус) міг не включити в top-3 задачу з дедлайном < 48 год. Перевірка фактів ядра вимагає таку задачу в `items` і для fallback, тож план відхилявся з `FALLBACK_INVALID`.
- **Причина:** порядок fallback зі спеки не враховував правило factCheck про термінові задачі.
- **Як виявили:** блокувальне зауваження рев'ю.
- **Як виправили:** `rulePlanOrder` ставить термінові першими, далі пріоритет → вік → in-progress ([[decisions]] D-031).
- **Як запобігти повторенню:** будь-який fallback проганяти через ту саму перевірку фактів, що й відповідь моделі (тест на задачі з дедлайном).

## 2. Smoke на порожній БД
- **Що сталося:** smoke (`npm run smoke:ai`) на порожній БД завершився `FALLBACK_INVALID`.
- **Причина:** немає активних задач, на яких агент може побудувати план.
- **Як виявили:** запуск smoke.
- **Як виправили:** `npm run db:seed`. Повідомлення про помилку неочевидне: не підказує про порожню БД.
- **Як запобігти повторенню:** кандидат на окрему маленьку задачу — зрозуміле повідомлення/перевірка порожньої БД у smoke.
